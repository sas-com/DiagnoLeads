# AI らしさの兆候

点検のときは上から順に当て、見つけた兆候を `file:line` と一緒に1行ずつ書き出す。各行は「兆候 → 直し方」で書く。直すときは、1〜8の節を、この順に1つずつ画面全体へ当てる（SKILL.md の手順5）。

- 管理画面の値は [dads.md](dads.md) に従う
- 公開サイトとビルダーの診断に当てる範囲は、SKILL.md の「対象と優先順位」に従う
- 共通部品で見つけた兆候は直さず、Issue に切り出す

**兆候ではないもの**（直さない）：
- Tailwind の段階の余白（`gap-1.5`・`py-2.5` などの 0.5 刻み）
- DADS のフォーカス（黒の outline と黄色）
- 日本語の見出しの 0.01〜0.02em の字間
- 略語の大文字（CSV・AI・AX・KPI・URL・ID）
- 読み込み中の `Skeleton`・スピナー・進み具合の棒
- AX サイトの `ax-*` の色・`rounded-full` のボタン・見出しの上の小さなラベル・ヒーローの配置

## 1. 余白

最初に直す。リズムが整うと、ほかの見え方が変わるため。

- Tailwind の段階に無い任意値（`mt-[13px]`・`ml-[7px]`・`h-[31px]`） → 段階の値
- 同じ一覧の中で、行の高さや間がばらばら → 高さと間を1つに
- グループが、自分の項目より隣のグループに近い → グループの中は狭く、グループ同士は広く
- 並んだカードの内側の余白がばらばら → 1つに
- 同じ種類のものの大きさ・間がばらばら → 同じものは同じ大きさに
- 節の上に大きな空き、下が窮屈 → 釣り合いを取る
- アイコン・ラベル・数字が列からずれる → それぞれ1本の列にそろえる（アイコンの箱の幅を各行で同じに）

## 2. 面と色

- 背景・カード・ボタン・選択中のメニューに、色相をまたぐグラデーション（紫から青・紫からピンクなど） → 1色の面
- 見出し・数字・ロゴにグラデーションの文字 → 主の文字色の単色
- 色つきの発光（`shadow-[0_0_20px_rgba(139,92,246,0.5)]`、絵文字の `drop-shadow`、光る錠剤形のバッジ） → 消す。奥行きは面の段階と細い枠線で
- 中身の後ろの放射状の色のにじみ・ぼかした塊 → 消す
- ネオンや濃い色の枠線 → 細い枠線（Solid Gray）
- 同じ色相のほぼ同じ色を何段も文字に使う（薄紫が5種類など） → 文字の色の3つの役割（[dads.md](dads.md) の「色」）
- 全部が強調されて、何も目立たない → アクセント（Green）は1画面に1〜2か所。主な操作・選択・一番大事な数字だけに使う
- 意味の無い所の成功・エラーの色 → 意味の色は、意味があるときだけ
- 白い内側のハイライトと色つきの影のすりガラスのカード → 枠線つきの普通の面

## 3. アイコン

- メニュー・ラベル・状態に絵文字（🏠 📥 🚀 💰 ⚠️ 📈 🔥） → lucide-react の線のアイコンか、無し
- 錠剤形のバッジや件数の中の絵文字（`18 👤`） → 数字だけ
- アイコンの大きさと色がばらばら → 大きさと線の太さを1種類に。色は文字の役割に合わせ、アイコンごとの色を付けない
- AI の機能に必ず付く ✨ → 消すか、説明になる所だけ普通のアイコン

## 4. 文言

文字と配置より先に直す。文言の長さで、大きさと配置が決まるため。unslop の英語の決まりを、日本語の画面向けに直したもの。

- 挨拶の見出し（「おかえりなさい、〇〇さん！👋」） → ページの名前か期間（「2026年11月」）
- 感嘆符（「！」「!!」） → 普通の文
- 比べる相手の無い増減（「+12%!!」「3件減!!」） → 「前月比 +12%」「前月より3件少ない」（比べる相手は見える文字で書き、`sr-only` だけにしない）
- 長いラベル・プレースホルダー（「なんでも検索…」） → 短く（「検索」）
- ラベル・ボタン・見出しの文末の「。」 → 付けない（複数の文の説明文には付ける）
- 宣伝の言葉（「劇的に」「シームレス」「魔法のように」「AI で革新」） → 実際に何をするか。「AI 搭載」を何にでも付けない
- 確かめられない主張（「1万社が利用」「10倍速い」、出どころの無い星5つ・アバターの列） → 本当かをオーナーに確かめる。本当なら控えめで具体的に書き、そうでなければ消す。報告に一覧で書く
- 作り物らしいデータ（連番の数字、「[X]」「サンプル太郎」） → 架空と分かる社名・人名、`example.com` のドメイン、実在しない電話番号、偏りのない数字。リポジトリは公開なので、実在の会社名・人名・個人を指すデータは使わない
- どこにでもある `PRO`・`NEW ✨`・`Beta 🚀` → 消すか、本当に要るときだけ控えめな文字のバッジを1つ
- 画面にじかに書いた文字列 → `locales/`（ja・en）に移す

## 5. 文字

- 太さ 500・600・800・900 → [dads.md](dads.md) の「文字」（400 と 700）
- 14px 未満の文字・14px の本文 → [dads.md](dads.md) の「文字」（本文 16px 以上）
- 1画面に大きさと太さが多すぎる → 段階から少数だけ。階層は大きさと色で付ける
- 英語の大文字のラベル（`NAVIGATION`・`PAID THIS MONTH`） → 普通の書き方（日本語のラベルなら日本語に）
- `tracking-wider` 以上の広い字間 → 既定の字間（日本語の見出しの 0.01〜0.02em はそのまま）
- 数字の書式がばらばら（`¥48,210` の隣に `¥124,860.40`、`07`） → 書式（桁区切り・小数の桁・単位）を画面の中で1つに、`tabular-nums`
- 小さい文字に負の字間 → 0 か少し広め
- 強調に斜体 → 色か太字 700

## 6. 配置

節と順番は変えない（SKILL.md の「してはいけないこと」）。節の中の強弱だけを直す。

- 同じ幅のカードに同じグラフや中身を並べるだけ → 主なグラフを1つ大きく、数字のカードや一覧を小さくして、幅に強弱を付ける
- 塗りのボタンが1画面に複数 → 主な操作だけ塗り、ほかは枠線か文字のボタン（[dads.md](dads.md) の「ボタンとフォーカス」）

## 7. 細部

- 検索・ボタン・カードの全部が丸い錠剤形 → 大きさに合わせた角丸。内側の角丸は、外側の角丸から内側の余白を引いた値に近い DADS の段階に（[dads.md](dads.md) の「影と角丸」）
- 件数・プラン・ショートカット・状態の光る錠剤形のバッジ → 控えめの文字か、キーキャップ
- 数字のカードごとにミニグラフ・小さな棒・アイコン → ラベル・数字・比べる相手を書いた増減だけ
- 虹色の棒・光る棒・丸い棒・英語の大文字の曜日のグラフ → [dads.md](dads.md) の「グラフ」。目盛りは控えめに
- どのグラフもアクセントの濃淡だけで、どれも目立たない → 主なグラフを1つ決め、アクセントは大事な系列（今月・追っている線）だけに付ける。ほかは [dads.md](dads.md) の「グラフ」の灰色と区別のしかた
- グラフのグラデーション・3D・影、データの更新日が無い、棒の原点が 0 でない → [dads.md](dads.md) の「グラフ」
- グラデーションのタイルに ✨ のロゴ、グラデーションの文字のロゴ → 製品の名前の文字と、単色の簡単なマーク

## 8. 動き

- 生きていない飾りの `animate-pulse`・`animate-ping`・明滅する光 → 止める。読み込み中の表示は残し、`motion-reduce:` で止まるようにする
- カードやボタンの `transition-all` → `transition-colors` などに絞る
- `hover:scale`・`active:scale` → ホバーと押下は、色か面の段階の変化だけ
- はねる・行き過ぎる動き → 1つの ease-out
- 読み込み時に全部が別々の方向から飛んでくる → 主な中身の短いフェードと小さな上昇を1回だけ
- 視差・浮遊のループ・スクロールで動く要素 → 動かさない
- 幅・高さ・top・left のアニメーション → 飾りならやめる。要る動きは transform と opacity で

## 公開ページとヒーロー（AX の公開サイト）

AX の公開サイトで直すのは、絵文字・根拠のない主張・宣伝の言葉だけ。配置・色・ボタンの形は、決定 `2026-10-11-ax-diagnosis-v2` のまま。文言を変える前にオーナーに確かめる。下の配置の兆候は、新しく作る公開ページで使う。出どころの無い「1万社が利用」・星5つなどの根拠のない主張は、「4. 文言」で扱う。

- 見出しの上の錠剤形のバッジ（「✨ 新しくなりました」） → 消すか、本当の知らせなら控えめの文字のリンク
- どの製品にも当てはまる見出し（「AI で業務を劇的に変える」） → この製品が誰に何をするかを、この製品の言葉で
- 見出しのグラデーション・光る動き → 単色
- ヒーローの後ろの浮いた塊・光る格子や線 → 無地か、製品の本物の画面1つ
- 3つ以上のボタン、ボタンの下にチップやアバターを積む → 主な操作1つと、副の操作を1つまで
- 絵文字・太字の題・あいまいな1行のカードの羅列 → 数を減らし、具体的な文言と線のアイコン（か無し）

## 画像

管理画面に画像の生成は使わない。注目させる所は、丁寧に描いたグラフ・整った数字・本物に見える中身で作る。

- つやのある 3D の塊・球・液体金属・紫の星雲 → 製品そのものか、何をするかを表す具体的な1つ
- AI を表すロボット・光る脳・回路の線・ホログラム → 消すか、AI が実際に出すものを見せる
- 文字・偽のボタン・偽のロゴを焼き込んだ画像 → 文字はページの文字に
- どの節にも画像 → 役に立つ所に1つだけ

## ひな形の見た目

兆候ではないが、整えたあとに誰も判断しないと落ち着いてしまう見た目。層を当てたあとに確かめる。

- 見出しが、製品の名前を替えても別の製品に通じる → この製品の言葉で、何をするかを書く
- 注目させる所が無く、全部が同じ灰色のカード → 主なグラフか大事な数字を1つ決め、そこにだけ色と手間をかける
- どの画面も同じ配置 → 画面の目的（一覧・詳細・分析）に合わせて強弱を変える
