# 本番 DB の戻し手順

本番の Supabase（DiagnoLeads v2）のデータが壊れた・消えたときに、正しかった時点へ戻す手順。アプリは Vercel。

- 作成：2026-10-23（#51「バックアップの確認」）
- **未確定**：Supabase のプランと毎日のバックアップの有無（オーナーが 10/24 に画面で確認）。確認の結果で下の A か B が決まる

## 1. まず決めること（戻すかどうか）

戻すと、その時点より後の書き込み（リード・診断の回答・ヒアリング・通知）はすべて消える。次の順で、戻さずに済まないかを先に考える。

1. **一部の行だけの問題か**：誤った更新・削除が特定の表・行だけなら、戻さずに SQL で直す（いつもの `00NN.sql` の手順。件数を確かめてから実行し、件数が合わなければ止まる SQL にする）
2. **全体が壊れたか**：DB が開けない、広い範囲のデータが消えた → 戻す
3. **いつまでが正しかったか**を決める：誤った SQL を流した時刻、デプロイの時刻（Vercel の記録）など

戻すと決めるのは **オーナー**。消える期間を了承してから進める。

## 2. 戻す前に（共通）

1. **社外からの送信を止める**：Vercel の Production の環境変数 `APP_TEST_MODE=true` にして再デプロイする。社外のメールアドレスからの診断・相談を受け付けなくなる
2. 戻す時点から今までに届いた問い合わせの通知メールを、営業に残しておいてもらう（戻した後に手で拾い直すため）

## 3-A. 毎日のバックアップがある場合（Pro プラン以上）

1. Supabase の管理画面 → プロジェクト → Database → Backups
2. 戻したい日のバックアップの **Restore**（PITR が有効なら時刻を指定）
   - プロジェクトの DB 全体が戻る。数分〜数十分、アプリから DB に接続できない
3. 終わったら「4. 戻した後」へ

## 3-B. 毎日のバックアップがない場合（Free プラン）

- Supabase 側に戻せるものがない。**10/21 の決定どおり、有料化を決めてから公開する**
- 有料化までのつなぎに、手動の控え（`pg_dump`）を取る場合
  - オーナーの承認のうえ、読み取り専用の接続で取る。接続文字列は表示しない
  - 対象は `public` と `drizzle` のスキーマ（`auth`・`storage` など Supabase の管理用スキーマは含めない）
  - 控えは社内の決まった場所に暗号化して置く。リポジトリ・チャット・Issue には置かない
  - 戻すときは、**新しい空の Supabase プロジェクト**（またはローカル）に流し込み、確かめてから Vercel の接続先を切り替える。本番の DB に上から流し込まない

## 4. 戻した後（共通）

1. 読み取り専用で件数を確かめる：`organizations`・`organization_members`・`users`・`leads`・`diagnostic_submissions`
2. マイグレーションの記録（`drizzle.__drizzle_migrations`）が、リポジトリの `drizzle/` の最後の番号までそろっているか確かめる。足りなければ、不足分を SQL Editor で流す（いつもの手順）
3. `APP_TEST_MODE` を元に戻して再デプロイする
4. 本番で診断を1件通し、確認欄（Turnstile）・通知・リードの表示を確かめる
5. 戻した期間に届いていた問い合わせを、通知メールから営業が拾い直す
6. #51（または新しい Issue）に、時刻・原因・戻した時点・消えた期間を記録する

## 既存の資料・スクリプトについて

- `docs/backup-strategy.md`（2026-01）は Neon を前提にした一般論。Supabase の実手順はこの文書を正とする
- `scripts/restore-database.sh` は、冒頭の説明（スキーマを消して作り直す）と動き（今の DB にそのまま流し込むだけ）が合っていない。**本番では使わない**。直すか消すかは、プランが決まってから決める
- `scripts/backup-database.sh` は全スキーマを `pg_dump` する。Supabase では管理用スキーマを除く必要があり、未検証

## 練習（できれば公開前に一度）

控えを取れる状態になったら、ローカルの Postgres に流し込み、件数が本番と合うことを確かめる（Claude。本番への接続はオーナーの承認のうえで1回だけ）。
