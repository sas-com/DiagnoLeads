## 1. マージを止めるべき指摘

### S1. 数字キーの意味が状態で入れ替わり、意図しない記録・取り消しが起きる【コード】

対象は `components/features/ai-employees/office-rooms.ts:150-153`（`fileChoices`）と `office-lead-file.tsx:99-123, 184-187` です。選択肢は並び順で数字が決まり、状態ごとに並びが変わります。決定 `2026-11-13-office-is-the-base` の「同じキーを続けて押しても、もう1件実行されたり取り消されたりしない」が守られているのは `1` キーだけです。

| 経路 | 何が起きるか |
|---|---|
| a. `2`（メールした）を2度押す | 記録が成功した時点で `2` は「いまの記録を取り消す」になり、2度目で記録が消えます。`busy` の間は無視されるので、応答が速いときに起きます（頻度は【推測】）。 |
| b. 記録 → `2`（取り消す）→ `1` | 取り消しが済むと並びが元に戻り、直前まで「ボードに戻る」だった `1` が「電話した」になります。戻るつもりで電話の記録が付きます。 |
| c. 取り消しが失敗したとき | `office-lead-file.tsx:91-97` の `onError` が outcome を `failed` にするため `recorded` が偽になり、取り消しの選択肢が消えます。同じ `2` でやり直すと「メールした」が記録されます。 |
| d. ファイルを開いた直後 | `contacts` を読む間は `canEdit` が偽で、選択肢は「1 ボードに戻る」だけです。読み終わると同じ位置が「1 電話した」に替わります（`key={choice}` で位置が動く）。ポインタの下で対象が入れ替わります。 |

今日の期限にも同じ原因の経路があります（`office-rooms.ts:170-178`、`office-room-due.tsx:124-139`）。済み → `2`（取り消す）のあと、直前まで「次の件へ」だった `1` が「済みにする」に戻ります。`2` は実行前が「あとで」、実行後が「取り消す」です。

直し方（最小。決定の文言の中で直せます）：
1. 取り消しは数字から外し、全部屋で同じ文字キーに固定します（案：`Z`。表示は「Z いまの記録を取り消す」）。
2. 取り消しのあとも、先頭は「ボードに戻る」（期限は「次の件へ」）のままにします。記録の選択肢は2番目以降に出します。
3. 読み込み中は、記録の選択肢を `aria-disabled` の枠として先に並べ、位置を動かしません。
4. 取り消しの失敗では `recorded` の状態と id を保ち、文を「取り消せませんでした。もう一度お願いします。」にします。
5. 選択肢の並びが変わった直後（300〜500ms）は数字キーを受けません。

期待効果：顧客の連絡記録に、意図しない記録と削除が入らなくなります。根本の案（数字を意味ごとに固定する）は「判断が必要な点 1」に書きました。

### S2. スタジオの「Esc 戻る」ボタンを押すと、確認なしで下書きが捨てられる【コード】

`office-studio.tsx:451-461` は `onClick={onClose}` で直接閉じます。Esc キーは `109-116` で一度警告します。決定 `2026-11-13-ai-employee-customization` の「一度確かめてから戻る」が、ボタンでは効きません。テストも Esc キーだけです（`office-studio.test.tsx:279`）。

直し方：ボタンも同じ関数を通します（未保存なら1度目は警告、2度目で戻る）。警告の間はボタンの文言を「変更を捨てて戻る」に替えます。

### S3. PR #1136 を検証のまま main に入れる場合【コード】

ドラフトのままなら、本実装の必須項目として扱ってください。

- **`3` キーの衝突**：`office-immersive.tsx:299-301` が `3` を 3D の切り替えに使っています。`office-rooms.ts:32-39` と決定では、`3` は営業フロアの鍵です。案：`V`（表示）に替えます。
- **検証パネルが全利用者に出る**：`office-immersive.tsx:716-775`。実際と違う状態を画面に出すので、決定 `2026-11-12-ai-employees-office` の「すべて実際の状態から作る」に反します。開発用のフラグの後ろに置きます。
- **読み込み中と失敗時の控えが無い**：`:77` の `dynamic` に `loading` が無く、`:475` で 2D を先に隠します。916 KB の読み込み中は空だけが出ます。エラー境界は `components/` と `app/` に1つもありません。WebGL が失敗すると、出社の画面ごと落ちるおそれがあります【推測】。最初のコマが描けるまで 2D を出したままにし、失敗したら 2D に戻して文で伝えます。

## 3. あとでよい指摘

- 件数を先に見せます。マーケティング室の選択肢に件数を付け、フロア案内の札に部屋の数字を出します（決定の「部屋の札に、その部屋の今の数字が出る」）。「社長の仕事」にも期限の件数を入れます。期待効果：押してから0件と分かる手戻りが減ります。

- 押せる範囲：見込み客ボードの「通常の表示の一覧で開く」（`office-room-leads.tsx:383-389`）と、顧客ファイルのメール・電話のリンク（`office-lead-file.tsx:269-286`）に `min-h-11` がありません。

- 2D と 3D で、同じズームでも画角が変わります。
- 選択肢のボタンに `aria-keyshortcuts` を付けます。フォーカスを置く報告の枠には `role="group"` と名前を付けます。

## 4. 推奨する型（部屋・ファイル・期限・スタジオ）

| 役目 | そろえる形 |
|---|---|
| 場所の名前 | 左上。小見出しが部屋、見出しが仕事。パネルの上に置く |
| 戻る | 右上に1つ。「Esc フロアへ戻る」。中で何か開いている間は「Esc ボードに戻る」 |
| 案内 | 左。顔・名前・状態 → 案内の1行 → 報告（フォーカスの行き先、結果もここ）→ 選択肢 |
| 選択肢 | 数字は実行と切り替えだけ。取り消しは `Z`、戻るは Esc。塗りは次に押すものだけ |
| ボード | 右。見出しと件数（`role="status"`）→ 中身 → 下に「通常の表示」へのリンクとページ |
| 狭い画面 | ボードが先、選択肢は下に固定。列はボードの幅で切り替える |

## 5. 判断が必要な点

1. **数字キーを意味ごとに固定するか**：根本の直し方は、数字を意味に固定することです（ファイルは 1 電話・2 メール・3 つながらなかった。実行のあとは無効にして残す）。決定の「実行のあとは、最初の選択肢を『戻る』にする」を書き換えることになります。想定リスク：期限の部屋で `1` の連打で進められなくなります。
2. **部屋に入る数字と、中の実行の数字**：社長のデスク（`1`）に朝の報告を置くと、`1` の2度押しで1件目が実行されます。入った直後は数字を受けない、という決まりが要ります。
3. **スマホの扱い**：出社の画面を作り込むか、「通常の表示」へ案内するか。M2〜M4 の深さが変わります。
4. **3D の範囲**：会話・部屋・スタジオも 3D にするか、フロアだけにするか。
5. **フォーカスの色**：DADS の規則（色を変えない）を出社の画面にも当てるか、暗い地のために順番を入れ替えるか。
6. **能力値・働き方のタブに「準備中」の札を出すか**：オーナーが出すと決めた項目なので、見せ方の確認が要ります。

## 良かった点

- 開いたときのフォーカスを報告の文に置くこと、`aria-disabled` でフォーカスを保ち、ハンドラ側でも止めていることは、全画面で一貫しています。
- 権限は API の `canEdit` で見ていて、読み取り専用の人には実行の選択肢が出ません。
- 期限の順番を開いたときに固定していること、結果を部屋の中の文で伝えることは、決定のとおりです。
- スタジオの能力値は、ゲージに読み上げ用の名前があり、残りのポイントが `aria-live` です。
- 3D の色・配置・感情は 2D と同じ定義から作られ、純粋な関数に分かれています。
