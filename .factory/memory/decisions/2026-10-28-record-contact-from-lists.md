### [UI] 一覧の行から連絡を記録する入口は「連絡を記録」のボタン1つとメニューにし、リードの画面は1タップのボタンのままにする（#863）
- **日付**: 2026-10-28
- **決定**: PR #891 の読み取り専用の UI/UX レビュー（2026-10-28）の推奨に沿って、Claude が決めた
  - 一覧の行から連絡を記録する入口は、`ContactRecordMenu`（「連絡を記録」のボタン1つ）にする
    - 押すとメニューが開く。並びは、電話した・メールした・つながらなかった・（区切り）・活動を記録
    - 対象は「今日」の画面の次の行動と商談予定の行。ダッシュボードの相談申込の行は #895 で合わせる
  - リードの画面のバーは、今までどおり1タップのボタン（`ContactQuickActions`）にする
  - メニューの中身・順番・言葉と、記録のトースト（リード名つき・元に戻す）は、どの画面でも同じにする
  - ボタンはリンクの中に入れず、行の右端に置く。押せる範囲は 44px、文字は 14px（決定 `2026-10-24-admin-dads`）
  - タッチでは pointerdown で開かず、タップ（click）で開く。スクロールの始まりで開かないようにするため
  - メニューの「活動を記録」で開くダイアログは、行ごとに持たず、欄に1つだけ置く（#998）
    - 置き場所は、読み直しで入れ替わる欄の中身の外（`RowActivityDialog`）。行が消えても、欄が失敗や空の表示に替わっても、入力ごと残る
    - 閉じたら、開いたメニューのボタンへフォーカスを戻す。行が消えていたら、欄の見出し（スクリプトからだけフォーカスできる）へ
    - 隣の行へは送らない。次の行動のチェック（#776）や次の行動の追加（#970）は、自分の操作で行が消えるので次の行へ進めるが、ここで行が消えるのはほかの人の操作か読み直しで、隣の行へ送ると、別のリードのボタンにいることに気づかない。見出しなら、欄が変わったことが読み上げで伝わる（#998 の UI/UX レビュー）
- **理由**
  - 行ごとに4つのボタンを並べると、スマホで行が折り返して重くなる。compact（32px・12px）は DADS に合わない
  - 一覧では2タップになる。ただ、スクロール中の誤記録を防ぐ軽い確認になり、リードの画面へ移るより手数が少ない
- **ルール**
  - 一覧の行に記録の入口を足すときは `ContactRecordMenu` を使う。`ContactQuickActions` の compact は新しく使わない
  - 行に印ごとの直す操作（「今日」の「注意が必要な商談」の受注予定日を直す・次の行動を追加など）を置くときは、印と同じ順に、リンクの外の行の右端に置き、2つのときは縦に積む（#999。横に並べると、スマホの行からはみ出し、sm〜md でリンクが細くなる）
  - 行から開くダイアログ（活動の記録、商談の次の行動の追加など）は、その一覧に1つ置き、欄の中身の外に出す（`useRowDialog`。#998）。`ContactRecordMenu` は開くことを一覧に頼む（`onRecordActivity`）ので、使う一覧は `useRowActivityDialog` と `RowActivityDialog` を置く
    - 閉じたあとの戻り先（開いたボタン・商談名・次の行）が画面に無いときは、「今日」では欄の見出しへ送る（#998）。商談の画面では、ボードが失敗の表示なら「再読み込み」（失敗の文を説明に付ける）へ、ボードか読み込み中なら画面の見出し「商談」へ送る（#1011）。見出しは、スクリプトからだけフォーカスできる。商談の画面で失敗の表示のときに見出しへ送らないのは、見出しと「再読み込み」の間に操作が5つあり、見出しの読み上げでは失敗が伝わらないため（「今日」の欄の見出しは、失敗の表示のすぐ上にある。#1011 の UI/UX レビュー）
    - 商談の画面では、ボード・失敗の表示・読み込み中のどれかが読み直しで替わり、フォーカスを持っていたもの（商談名・「再読み込み」など）が一緒に消えたときも、同じ戻り先へ送る。「再読み込み」でボードに戻ったときは、失敗の前にフォーカスがあった商談名（ダイアログから戻ったときは、その商談の名前）へ戻す。次の行動の追加は読み直しを待たずに閉じるので、閉じたあとの読み直しの失敗もこれで受ける。フォーカスがその前にボードの外へ移っていたら動かさない。Radix のメニューや Select がフォーカスを戻すのは setTimeout のあとなので、その後で救う（#1011）
    - 商談の画面の「商談を作成」（ヘッダー・空の表示から開く）も、閉じたら開いたボタンへ戻す。最初の商談を作ると空の表示のボタンが消えるので、そのときは作った商談の名前へ、それも無ければ上と同じ戻り先へ送る。リードの商談のカードの「商談を作成」は、作成のあともボタンが残るので、ボタンへ戻す。新しい商談を「失注」で作るときは、フォームが閉じて失注の理由のダイアログが開くので、フォームが閉じたときではなく、理由のダイアログで保存して閉じたときに戻す（理由を取り消したら、フォームに戻る）（#1028）
    - 商談のボードの移動の問い（受注・失注・再開・SQL判定）を閉じたときは、カードの移動ボタンへ戻す（ドラッグで問いが出たときは、問いを開いた時点のフォーカスの位置へ）。そこが無いときは、商談名、失敗の表示なら「再読み込み」、ほかは画面の見出しの順に送る。「再読み込み」でボードが戻ったら、その商談の名前へ（#1026）
      - そこが無いのは、問いを開いている間にボードが読めなくなったとき・読み直されたとき、商談がボードから消えたとき、保存したあとに商談がボードから外れたとき（閉じた日が直近30日より前。#1045）
    - 「今日」の欄の読み直し、読み直しが成功して行・カードが消えたとき、商談名以外にあったフォーカスを覚えることは、まだ扱っていない（#1027）。商談の詳細のステージの移動も、まだ扱っていない（#1044）
  - 入口は、リードを編集できる人（`useLeadAccess` の `canEdit`）にだけ出す
  - 1タップの記録では、次の行動を完了にしない。連絡と完了は1対1ではないため（「つながらなかった」は完了ではない、など）。記録の続きで完了にする流れは #776 で決める
  - 商談予定の行から何を記録させるか（ヒアリング・活動）は、#776 の二重計上の扱いと一緒に決める。それまでヘルプは「打ち合わせで聞いたことはヒアリングとして記録する」とする
- **却下案**
  - 行ごとに4つのボタンを並べる：スマホで行が折り返す
  - 分割ボタン（「電話した」＋▼）：よく使う種類が人によって違い、幅も取る
