### [Leads] 営業の手引きの「Web 化のセキュリティの不安」：登録の前に決める5点（#464）
- **日付**: 2026-10-25
- **決定（10/25 オーナーの指示「このセッションで立てて、まだ開いている Issue は全て解決してください」を受けて、Claude の推奨を採った。違えば #464 で知らせてもらう）**:
  1. 移行のあとの保守（更新・弱点の見張り）を受けるかは、保守の契約で決めるまで言わない。手引きに「保守もお受けしています」は足さない
  2. VPN からだけ使う形、社内のサーバーに置く形、会社のアカウントでのログイン、多要素認証について、初回で「選べます」とは言わない。「そういう形もあります。御社の決まりを伺ってから決めます」までにする
  3. 当社が作る・保守するシステムで PHP を使っているかは、その場で答えず持ち帰る。確認先はエンジニア部門
  4. 修正版の番号などの技術の細部は、営業（協力会社を含む）は話さない。エンジニアが同席する相談に回す
  5. セキュリティの不安が出た案件は、次の相談にエンジニアの同席を社内で頼む。お客様への言い方は「内容に応じて、エンジニアも同席します」のまま
- **理由**: 保守の体制と、当社が受け持つ技術の範囲は、まだ決まっていない。決まるまでは、約束にならない言い方にする（#296、決定 `2026-10-25-access-consult-open-points` の4）
- **ルール**:
  - 手引きの本文は、リポジトリ・Issue・PR に書かない（決定 `2026-10-15-sales-playbook-in-db`）。文案はセッションでオーナーに渡し、設定画面から登録する
  - 保守の体制が決まったら、この決定を置き換え、1 と 5 の言い方を見直す
