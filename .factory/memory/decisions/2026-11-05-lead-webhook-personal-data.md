### [Security] lead.* の Webhook で送る個人情報の扱い

- **日付**: 2026-11-05（判断は2026-10-29。オーナーの判断）
- **背景**: #308（PR #361）で、lead.* の Webhook がリードの個人情報（メール・氏名・会社名・電話番号）を、顧客が登録した外部 URL へ送るようになった
- **決定**:
  1. **位置づけ**: リードの個人情報を扱う事業者は顧客の組織で、当社は委託先とする。送信先は顧客自身が登録した URL なので、当社による第三者提供ではなく「顧客の指示による送信」と整理する。最終的には法務部門の確認を前提とする
  2. **設定時の確認**: lead.* を選んだら送る項目を表示し、確認のチェックがないと保存できないようにする。サーバー側でも確かめ、誰がいつ確認したかを監査ログに残す（#917）
  3. **保存**: 配信が終わったら（成功、または再送を使い切って失敗）、配信履歴の送信内容から個人情報を消す。リード ID・イベント・結果・日時は30日間残す。リードを削除したら、再送待ちの配信からも消す（#918）
  4. **遅延と順番**: キューに回った配信は最大で約24時間遅れ、順番も保証しない。これを仕様として明記し、受け取る側には `updatedAt` で新しい方を採ってもらう。再送の頻度を上げるのは、ワークフローエンジンの段階1でまとめて行う（#919）
- **判断の材料（2026-10-29に本番 DB を件数だけ確認）**: Webhook は0件、配信履歴も0件、組織は1件だった
  - 既存の購読者に、知らないうちに個人情報が届き始めたという問題は起きていない
  - #309 で直した配信履歴の漏えいも、見られる相手（ほかの組織）がいないため、本番ログは調べないで終える。ただし、過去に削除された組織や Webhook があったかは確かめられない（監査ログに記録がない）
- **却下案**:
  - 当社による第三者提供と整理する：リード本人の同意を取る仕組みが要り、それができるまで機能を止めることになる
  - 画面に表示するだけにする：顧客が確認したことを示せない
  - 配信履歴を30日そのまま残す：削除したリードの個人情報が残り、組織のメンバー全員に見える
  - lead.* の配信履歴だけ7日で消す：結果も一緒に消え、失敗の調査がしにくい
  - 再送を今すぐ毎時にする、または Vercel Pro にする：段階1の設計と別に仕組みが増える。費用もかかる
- **ルール**:
  - lead.* で送る項目を増やすときは、#917 の確認画面に出す項目も合わせて変える
  - 配信履歴に個人情報を残す変更は、この決定を見直してから行う
