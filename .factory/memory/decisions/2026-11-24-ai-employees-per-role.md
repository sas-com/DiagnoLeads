### [Architecture] 1つの役割に AI社員を3人まで採用できるようにする（#1282）
- **日付**: 2026-11-24
- **決定**（オーナーの判断。2026-11-16 に「1役割に複数人を許す」、2026-11-24 にこのセッションで選択肢から選んでもらった）:
  1. 上限は **1つの役割に3人**
  2. 同じ役割に複数人いるとき、部屋の案内と報告は **等級の一番高い社員** が受け持つ。同じ等級なら先に採用した社員。休止中の社員は受け持たない
  3. **段階に分けて出す**
- **実装で決めたこと**:
  - 社員は役割の席に座る（`ai_employees.seat`、0〜2。`AI_EMPLOYEE_SEATS_PER_ROLE`）。席は保存し、解雇しても同じ役割のほかの社員の席は動かさない。一意は (組織・役割・席)。採用は空いている一番小さい席を取り、同時の採用で同じ席を取り合ったら、負けた方が次の空きを取り直す
  - 上限は定数 `AI_EMPLOYEES_PER_ROLE`。画面が役割をキーに社員を持っている間（名札・名簿・会話・3D）は **1のまま** にする。先に上げると、同じ役割の2人目の名札と詳細で別の社員を操作してしまう（洗い出しの結果）
  - 0043 では、古い一意索引 (組織・役割) を残す。上限が1のうちは意味が同じで、マイグレーションの適用からデプロイまでの間も、古いコードの採用（`ON CONFLICT (organization_id, role)`）が動き続けるため。上限を上げる段で消す
  - 段階：1. データと API（席・上限1）→ 2. 画面を社員 id で持つ（見た目は変えない）→ 3. 2D の席 → 4. 3D → 5. 部屋の受け持ちを決め、上限を3に上げ、古い索引を消す
- **却下案**:
  - 席を保存せず、採用順で毎回並べる：解雇のたびにほかの社員の席が動き、同時の採用で上限を超えうる
  - 索引だけ外して上限を上げる：今の採用の `ON CONFLICT` が対応する索引を失って全部エラーになり、画面は後勝ち・先勝ちが混ざって別の社員を操作する
- **まだ決まっていないこと**:
  - 仕事（works）を載せるとき、同じ役割の誰が実行するか（全員か、受け持ちの1人か）
  - 研修室・ラウンジ・充電ステーションが上限まで埋まったときの置き場所（3段目で決める）
