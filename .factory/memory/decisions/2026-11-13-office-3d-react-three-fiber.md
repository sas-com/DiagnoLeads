### [UI] AI社員オフィスの 3D は three.js + React Three Fiber で作る。出社の画面で切り替えたときだけ読み込み、ロボットはコードで組み、2D を控えに残す（#1135 の検証）
- **日付**: 2026-11-13
- **決定**（オーナーの指示。2026-11-13「3Dゲームエンジンを採用して AI社員が部屋を移動するアクションや感情を表現できるようにしたい」。参考として react-three-fiber の入門の記事を挙げ、検証用の新しいブランチとドラフト PR を許可した）: AI社員オフィスの 3D は、three.js + React Three Fiber（`three` 0.187.0・`@react-three/fiber` 9.8.2）で作る。まず検証（P0）を行い、本実装に進むかは結果を見て決める
- **理由**: 画面が React（19.2）で、文字・ボタン・翻訳・権限は DOM のまま残したい。要るのは「1フロアと数体のロボットを動かす」ことで、物理やエディタは要らない。three.js は MIT で、React Three Fiber は React 19 に対応している
- **却下案**（比較は #1135）:
  - Babylon.js：エンジンとしての機能は最も揃うが、パッケージが大きく、React との結び付きが弱い
  - PlayCanvas：強みのクラウドのエディタが別サービスで、コードで組む作りと合わない
  - Unity・Godot：出力が WASM で、本番の CSP（`wasm-unsafe-eval` なし）を緩める必要がある。ビルドと、文字・翻訳・権限の作りが二重になる
  - `@react-three/drei`：要ると分かるまで入れない（検証では、名札と頭上の印を canvas のテクスチャで描いて足りた）
- **ルール**:
  - 3D の部品は `next/dynamic`（`ssr: false`）で、3D に切り替えたときだけ読み込む。ほかの管理画面と、出社の画面の 2D には載せない
  - WASM・Worker・blob を使うもの（Draco・KTX2 の展開、物理エンジン、ナビメッシュ）を入れない。入れるなら CSP の変更になるので、`security-specialist` のレビューを通す
  - ロボットは外部のモデルを使わず、見た目の項目（#1134 の `RobotLook`）からコードで組む。色の表・役割の装備・状態の灯りの色は、2D と同じ定義（`office-robot.ts`・`office-prims.ts`）を使う
  - 床・机・席は 2D と同じ配置のデータ（`office-map-layout.ts`）から作る。2D と 3D で場所がずれないようにする
  - 歩く道筋（`office-nav.ts`）と感情（`office-emotion.ts`）は純粋な関数にして、単体テストで確かめる（WebGL は jsdom で動かない）
  - 感情は実際の状態と出来事からだけ決める。成功した作業にだけ「達成」を出し、止まった作業と休止中は、ほかの出来事で上書きしない。性格（#1134）は動きの大きさにだけ効かせる
  - 3D の絵は飾り（`aria-hidden`）。情報は必ず DOM にも出す。「動きを減らす」設定では歩かせずに移す
  - 2D の絵は消さない。WebGL が使えないとき・非力な端末・利用者の選択のための控えにする
- **検証で分かったこと**（P0。2026-11-13、手元）:
  - 読み込み：three.js と React Three Fiber は1つのチャンクにまとまり、916 KB（gzip で 240 KB）。出社の画面を開いただけでは読み込まれず、3D に切り替えたときに1回だけ読み込まれた（本番ビルドで確かめた）
  - CSP：本番の CSP のまま動いた（違反 0 件）
  - 描画の速さ：手元の確認は GPU の無い環境のソフトウェア描画で、毎秒 7〜58 コマと場面で大きく変わった。**実機での速さは測れていない**。本実装の前に、実機（非力なノート PC・スマホ）で測る
  - 依存の追加とスキーマの変更を同じ PR に入れない決まりなので、検証は PR #1105 の上に積んだ別の PR にした
- **レビューで決めたこと**（2026-11-13、`security-`・`ui-ux-`・`architecture-`・`ci-devops-specialist`。マージを止める欠陥は無し）:
  - 3D の切り替えのキーは V（数字は部屋の鍵。3 は営業フロアに使う）。切り替えと検証用のパネルは開発時だけ出す（`OFFICE_3D_TRIAL`。本番ビルドでは出ず、3D のチャンクも要求されない）。本番で出すかどうかはオーナーが決める
  - 3D の最初の1コマが描けるまで 2D を残し、読み込みの失敗・WebGL が使えない・描画のエラーのときは 2D に戻して、そう伝える（`Office3DBoundary`）。検証をやめたら、パネルで仮に変えた状態と出来事を捨てる
  - 検証用の部品は `office-3d/office-3d-trial.tsx` に置く（three を値で読むのは `office-canvas-3d.tsx` と `robot-3d.tsx` だけ）
  - React Three Fiber が実行時に組む相手は、`package.json` の React ではなく Next.js が抱える React（canary）。**Next.js を上げたら、3D を手で開いて確かめる**（peer の検査も単体テストも気づけない）。本実装に進むなら、本番ビルドで 3D を開く E2E を1本足す（canvas が出る・ページのエラーと CSP 違反が無い、まで）
  - マージの順番：PR #1105（スキーマ）→ 本番に 0039 → #1105 をマージ → #1136 に main を取り込み、base を main に替えて push（base の付け替えだけでは CI は始まらない）。今の base（`claude/**`）では CI が動かないので、そのままマージしない。マージの前に、Vercel の Bun の版で `--frozen-lockfile` を確かめる（決定 `2026-10-21-frozen-lockfile-on-vercel`）
  - `bun.lock` は PR #1117（Storybook）とぶつかる。後から入るほうが、main の `bun.lock` を取ってから `bun add` をやり直す
- **まだ決まっていないこと**: 本実装に進むか（実機の速さを見てから）、ロボットをコードで組む立体のままにするか（デザイナーの 3D モデルにするか）、社長のアバター、音。検証用のパネル（状態と出来事をこの画面の中だけで切り替える）は検証のためのもので、本実装では実際の状態の変化につなぐ
