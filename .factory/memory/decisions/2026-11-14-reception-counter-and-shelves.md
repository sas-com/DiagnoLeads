### [UX] 総務・受付を、バックオフィスの仕事の部屋にする。窓口で数字を報告し、棚（期限・メンバーと招待・設定の扉）を選ぶ（Epic #1195）
- **日付**: 2026-11-14
- **きっかけ**: オーナーの指示「AI社員オフィスに適したバックオフィス機能をリファクタリングお願いします」。範囲を4つの選択肢で確かめ、オーナーが「部屋の中身を広げる」を選んだ（ほかは：コードの整理だけ／AIバックオフィスの仕事を作る／通常の表示も含めて全体）
- **決定**（オーナーの判断）:
  - 総務・受付（鍵 5）は、期限を渡すだけの部屋から、バックオフィスの仕事の部屋にする。期限を1件ずつ渡す形（#1133）は、棚の1つとして残す
  - 決定 `2026-11-14-concept-and-flow` の1「総務・受付は…今の形のまま」は、これで一部変わる（期限の渡し方は同じ。入ってすぐは窓口になり、棚が増える）。社長のデスクとの分け方（デスクは「今日」の全体）は変えない
- **形**（#1196）:
  - **窓口**：AIバックオフィスが、自分の期限が今日までの次の行動の件数（うち過ぎた件数）・メンバーの人数・招待中の件数を、記録されている値で伝える。選択肢は 1 期限・2 メンバーと招待・3 設定（`SHELF_KEYS`）
  - **棚**：期限（今までの部屋をそのまま）／メンバーと招待（読むだけ）／設定（通常の表示のページへの扉。`SETTINGS_DOORS` の決まったパスだけ。並びはサイドメニューの総務・受付と同じ）
  - Esc は1段ずつ：棚 → 窓口 → フロア
- **ルール**:
  - 窓口の数字のキーは棚を「開く」だけで、何も実行しない。だから同じ数字を、開いた棚の実行（期限の棚の 1 済みにする・2 次の件へ）に使える。棚の中でのキーの意味は、今までどおり場面の状態で変えない
  - 読めなかった数字と、見る権限が無い数字は言わない（招待は管理者とオーナーだけ。API の答えが FORBIDDEN なら、件数も一覧も出さない）。上限（200件）を超えて全部を読めていないときは、過ぎた件数を言わない
  - 窓口と棚は同じ問い合わせを使う（窓口で伝えた数字と、棚で見える中身が合う）。部屋のために API を足さない
  - 棚が開いている間は、見出しの「Esc フロアへ戻る」の Esc の印を出さない（顧客ファイルと同じ `onFileOpenChange`）
  - 棚を開いた・閉じたあとのフォーカスは報告の文に置く
- **棚の中の操作**（#1197。オーナーの判断、2026-11-14。4つの選択肢から選んでもらった）:
  - 棚でできる操作は、**招待中の取り消しだけ**。招待を送る・役割の変更・メンバーの削除は、通常の表示のメンバーの画面に残す（棚の扉から開く）
  - 理由：出社の画面は、キーだけで操作に届く（決定 `2026-11-14-office-entry-same-site-only`）。解雇は「相手が知らない名前」を打たせるので守りになるが、招待は打つメールアドレスそのものを相手が選べるので、同じ守りが効かない。外の人が組織に入ると、リードの個人情報を読める。解雇より重いので、出社の画面には入れない
  - 却下：最後の送信をクリックだけにする（キーだけで操作する人は通常の表示で招待することになる）／棚からは「メンバー」の役割だけ招待できる（外の人が入る筋道は残る）／解雇と同じ扱いで受け入れる
  - 取り消しの形：メンバーと招待の棚の 1（`REVOKE_KEY`）は欄を開くだけ。招待中の相手のメールアドレスを入力するまで、実行のボタンを閉じる（`invitationNamed`。全角と半角・大文字と小文字・前後の空白は問わない。アドレスの全体が合うこと）。権限が無い人（招待が見えない人）には選択肢を出さず、招待中が無いときは閉じる
  - 欄が開いている間、棚のキーは Esc のほかを使わない（打った文字になる）。Esc は欄を閉じて棚へ戻る。保存している間は、Esc と「棚に戻る」を閉じる（要求はもう出ている。会話の人事と同じ）
  - 失敗は、サーバーの文ではなくコードで言い分ける（NOT_FOUND は「もう取り消されているか、承認されています」）。終わったら招待の一覧を読み直す（窓口の数字も同じ問い合わせ）
  - 入力欄は標準の検証を止める（`noValidate`）。標準の検証は、何も読み上げずに送信だけを止める。種類は `type="text"` と `inputMode="email"` にする（メールの欄にすると、ブラウザが覚えているアドレスを候補に出すことがあり、矢印と Enter で入力できてしまう）
  - **守れないこと**（`security-specialist` のレビュー。コードから組み立てた筋道で、打鍵は試していない）：招待中のアドレスを知っていて、出社の画面に届く打鍵を決められる相手は、5 → 2 → 1 → アドレス → Enter で取り消しに届く。解雇の「守れないこと」と同じ型。消えるのは招待1件で、送り直せる（解雇より軽い）ので、今の形のままにする
  - 出社の画面に、招待の送信・役割の変更・メンバーの削除を足したくなったら、この決定と `2026-11-14-office-entry-same-site-only` に照らして、先にオーナーに確かめる
- **却下案**:
  - 窓口を置かず、期限の画面に棚の切り替えを足す：期限の棚は数字を実行に使っている（1 済みにする）。同じ場面で数字を切り替えにも使うと、キーの意味が状態で変わる
  - 期限があるときは窓口を飛ばして期限の棚から始める：入るたびに始まる場所が変わる
- **あとで決めること**:
  - AIバックオフィスの仕事（期限の見張り）を動かす（#1198。今は仕事が動いておらず、採用しても「研修中」）
