### [UI] マーケティング室は、AIマーケターが集客を報告する部屋にする。報告は過去30日の数字、ボードは流入元・進み具合・施策・見込み客で、鍵は 1〜8（Epic #1199・#1200・#1201・#1202）
- **日付**: 2026-11-14
- **きっかけ**: オーナーの指示「AI社員オフィスに適したマーケティング機能をリファクタリングお願いします」。範囲が4通りに読めた（部屋の中身を作り直す／コードの整理だけ／AIマーケターの自律の仕事／通常の表示も含めた全体）ので、選択肢で確かめた
- **決定**（オーナーの判断。2026-11-14、選択肢から「部屋の中身を作り直す」）:
  - マーケティング室（鍵 2）を、マーケターの役目（見込み客を見つけ、追う価値のある相手を見極める）の部屋にする。AIマーケターが集客の数字を報告し、社長が選択肢でボードを切り替える
  - 既存の分析の API を読むだけで、API は足さない（決定 `2026-11-13-office-is-the-base` の「部屋のために API を足さない」のまま）
  - Epic と子 Issue に分けて進める（#1199）
- **実装で決めたこと**（#1200。こちらで決めた。オーナーの確認の前）:
  - **報告**：過去30日に登録された見込み客の数、そのうち関心あり（MQL）以上に進んだ数と商談に進んだ数、いちばん多い流入元、流入元の記録が無いものの数（1件以上あるときだけ）。期間の言い方は分析の画面と同じ「過去30日」。`analytics.getConversionFunnel` と `analytics.getAcquisitionCost`（どちらも 30日）の答えだけから作る（`marketingReport`）。前の報告（今週の新規・相談の申込・未着手の件数）と、件数だけの `leads.list` 3本はやめた
  - 「いちばん多い流入元」に、流入元の記録が無い見込み客は選ばない（記録が無いことは流入元ではない）。件数は報告で別に伝え、流入元ボードには「流入元の記録なし」の行として出す（「費用が未記録」と紛れない名前にした）
  - **ボードは3つ**：流入元（流入元ごとの見込み客の数と割合・SQL・受注・獲得費用。API が `deals` を返した人にだけ受注額と ROI）、進み具合（見込み客 → MQL → 商談 → SQL → 受注 の到達数）、見込み客（今までの5つの見方）
  - **鍵は 1〜7**（`MARKETING_CHOICES`）：1 流入元・2 進み具合・3 未着手・4 相談の申込・5 今週の新規・6 自分の担当・7 すべて。同じ数字は、どのボードを見ていても同じものを開く。前は 1〜5 が見込み客の見方だった（部屋ができた翌日なので、番号を付け替えた）。これから選択肢を足すときは、今の数字を変えずに末尾に足す（数字のボードの鍵が 1・2・8 と離れても、動かさない）
  - 部屋を開いたときのボードは流入元（報告と同じ話題）。前は見込み客ボードの「未着手」
  - 選択肢の並べ方：集客の2つは1行ずつ、見込み客の5つは「見込み客を見せて」の下に2列（高さ 768px の画面で、左の案内がスクロールせずに収まる）
  - 数字のボードは読むだけで、何も実行しない。期間の切り替えと細かい内訳は、通常の表示の「分析」へのリンクで開く
  - 数字が無い期間は、0 を並べた表を出さず、無いと伝える
  - **言葉**：部屋の中でも「流入元」と呼ぶ（リードの詳細・分析の画面と同じ。Issue では「獲得元」と書いたが、3つ目の呼び名を増やさない。#1172）。リードは部屋の中では「見込み客」
- **コードの分け方**（#1142 の方向に、マーケティング室の分だけ寄せた）:
  - 部屋 `office-room-leads.tsx`（報告・選択肢・鍵の配分。ファイルと部品の名前 `OfficeRoomLeads` は前のまま。出社の画面の入れ物 `office-immersive.tsx` を触らないためで、部屋の登録表を作る #1142 で付け替える）／ボード `office-board-leads.tsx`・`office-board-figures.tsx`／純粋な関数 `office-marketing.ts`
  - 鍵は、出社の画面 → 部屋 → ボードの順に渡す（`useRoomKeys`。数字は部屋、矢印は見込み客ボード）
  - 見込み客ボードのページは部屋が持つ（顧客ファイルを開いている間、ボードは画面から外れる）
- **並行する作業との重なりを避けるために、後回しにしたこと**（オーナーの指示 2026-11-14「他のセッションと連携してください」）:
  - open な PR #1165・#1166・#1178（導線の整理、Epic #1161）が `office-immersive.tsx`・`locales/*/aiOffice.json` の `room.work`・利用ガイドのオフィスの記事の同じ行を触っている。ぶつかるのは「部品の名前の差し替え」と「部屋の仕事の名前の変更」だけだったので、この2つを外した（`git merge-tree` で3本とも衝突 0 件を確かめた）
  - 部屋の仕事の名前（`room.work.marketing`「リード管理」）は、PR #1206 では変えなかった（同じ行を触る PR が全部入ったあと、#1213 で「集客と見込み客」に変えた）。当時の判断：PR #1165 のマージのあとに「集客と見込み客」へ変える（Epic #1199 の残り。#1172 の呼び名の表とも合わせる）
  - 部品の名前（`OfficeRoomLeads`・`office-room-leads.tsx`）の付け替えは #1142
- **`ui-ux-specialist` のレビュー（読み取り専用。blocker なし）で直したこと**。次の部屋のボードでも同じにする:
  - 壁のボードが替わったことは、作り直されない左の案内の側から伝える（`<output>` に「壁のボード：…」）。ボードは替えるたびに作り直されるので、ボードの中の live 領域は、中身と一緒に差し込まれて読まれない
  - フォーカスを持ったボードが壁から外れるとき（行やスクロール領域にフォーカスがあるまま数字のキーで替えたとき）は、フォーカスを報告の文に戻す
  - スクロールする表の領域は、`tabIndex={0}`・`role="group"`・名前の3つを組にする。名前は、その領域で矢印キーが実際にすることを言う。行を選べるボードでは、矢印は行を移り、端の行ではブラウザーに返してスクロールさせる（`focusNextRow`。#1214：#1211 で行を選べるようにしたとき、矢印を必ず使う作りにして、表の下の注記にキーボードで届かなくなっていた）
  - 権限が無いときは、報告も「権限がありません」と言う（「読めませんでした」にしない）
- **オーナーに確かめること**（レビューの「判断が必要な点」。決まるまで今の形）:
  - 部屋に入った瞬間の「未着手・相談の申込の件数」が見えなくなった。選択肢の札か報告に戻すか（件数だけの問い合わせが2本増える）。最初のボードを流入元にするか未着手にするかも同じ判断
  - 2つのボードで SQL の数え方が違う（進み具合は「SQL と判定、または受注」、流入元は「SQL と判定」だけ）。注記で説明するか、API の定義をそろえるか
  - 流入元ボードの「受注」（状態が受注の見込み客の数）と「受注額」（受注した商談の金額）の呼び分け。分析の画面は前者を「成約」と呼ぶ（#1172 の用語の表で合わせる）
- **施策ボードと、流入元の行から見込み客を開く動き**（#1201・#1202。オーナーの指示 2026-11-14「#1201 と #1202 も進めてください」。形はこちらで決めた）:
  - **施策ボードは鍵 8**。QR キャンペーンと代行会社を、1つのボードに2つの表で並べる（数字のキーは 9 までなので、1つ残す）。表ごとに期間が違うので、表の見出しに期間を書く：QR キャンペーンは作成からの累計（`distribution.listCampaigns` の読み取りと新規、`analytics.getQrCampaignBreakdown` の内訳）、代行会社は過去30日（`analytics.getAgencyPerformance`）
  - 施策ボードの3本の問い合わせは、ボードを開いたときにだけ出す（報告は使わない）。内訳だけ読めないときは、読み取りと新規は出し、内訳は「—」にして、読めなかったと伝える
  - キャンペーンの登録・変更は部屋に移さない。ボードの下から、通常の表示の「QR キャンペーン」と「分析」を開く。総務・受付の設定の棚の扉（PR #1203）とは役目が違う（あちらは設定、こちらは成果を読むだけ）
  - 選択肢の並べ方：集客の数字の3つ（1 流入元・2 進み具合・8 施策）を「集客の数字を見せて」の下に2列、見込み客の5つ（3〜7）を「見込み客を見せて」の下に2列。鍵の番号は並びと合わないが、番号は動かさない
  - **流入元の行を開く**：上下の矢印で行を選び、Enter で、その流入元の過去30日の見込み客を見込み客ボードに出す（`leads.list` の `inflowSource` と `createdFromDay`）。期間の始まりは、分析の API が数え始める時刻と同じ日本の日付にする（`marketingPeriodFromDay`。テストで `analyticsPeriodStart` と突き合わせている）
  - 開けるのは、流入元の値が `INFLOW_SOURCES` にある行だけ。「流入元の記録なし」の行は、`leads.list` に絞る条件が無いので開けない（API を足さない）。開けない行はボタンにせず、注記に書く
  - 流入元から開いた見込み客ボードは、選択肢の切り替えではなく、流入元ボードの「1段奥」。選択肢は 1（流入元）が押されたまま。Esc は1段ずつ戻る：顧客ファイル → その流入元の見込み客 → 流入元ボード（フォーカスは開いた行）→ フロア。奥にいる間は、出社の画面の「フロアへ戻る」に Esc の印を出さない（`onFileOpenChange`）
  - 見込み客ボード（`office-board-leads.tsx`）は、見方の名前ではなく、絞り込み（`LeadListFilters`）と名前を受ける形にした。ほかの入口から見込み客を出すときも、絞り込みを渡す
- **却下案**:
  - 選択肢を2段にする（1〜3 でボード、見込み客の見方は別のキー）：キーの決まりが増え、「同じ数字はいつも同じ」が崩れる
  - 見込み客の見方から「自分の担当」「未着手」を外す（営業の仕事に近い）：営業フロア（#1171）ができるまで、行き先が無くなる
  - 部屋の札の数字・件数のための API を足す：決定の例外になる。#1142 の「件数の問い合わせ」の項に残す
- **ルール**:
  - 部屋の数字は、分析の API の答えをそのまま出す。部屋の側で数え直さない（割合の丸めだけ）
  - 商談の金額（受注額・ROI）は、API が返した人にだけ出す。画面の側で権限を判定しない
  - 次にボードを足すときも、この型で足す（数字のボードは `FigureBoard` の枠、鍵は末尾）
