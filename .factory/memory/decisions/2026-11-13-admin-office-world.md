### [UI] 管理画面と認証の画面を AI社員オフィスの世界観にする。ライトは昼、ダークは夜。アクセシビリティの基準は DADS のときの数字を引き継ぐ（#1120）
- **日付**: 2026-11-13
- **決定**（オーナー判断。2026-11-13「管理画面の実物も変える」「全て AI社員オフィスの世界観に統一してください。没入感を上げるための改善お願いします」）:
  - 管理画面（ログイン後の画面）と認証の画面の見た目を、AI社員オフィスの世界観に統一する。決定 `2026-10-24-admin-dads`（管理画面を DADS にする）を置き換える
  - ライトは昼のオフィス（大理石の白い地・紺の文字・真鍮の線）、ダークは夜のオフィス（濃紺の地・真鍮の灯り）
  - 画面は部屋に対応させる：メニューは「フロア案内」で、機能の名前を主に、部屋の名前を添える（ダッシュボード・分析＝社長室、今日＝社長のデスク、リード管理＝マーケティング室、商談・売上予測・顧客探し＝営業フロア、設定＝総務・受付）
- **決定**（実装。オーナーの答えが無い点は案のとおりにし、あとで変えられる形にした）:
  - メニューは昼も夜も紺（建物の柱として変えない）
  - 専用の書体は入れない（依存と読み込みを増やさない。入れるかは別に決める）
  - AX の公開サイト（`.ax-site`）・診断ビルダー・メールは対象外（利用者と決まりが別。広げるときはオーナーに確かめる）
- **理由**: 業務アプリの見た目のままでは、AI社員オフィスだけが別の世界になる。管理画面全体を同じ世界にして、没入感を上げる
- **却下案**:
  - デザインシステムの見本と Storybook だけを世界観に合わせ、管理画面の実物は DADS のままにする：オーナーが実物も変えるほうを選んだ
  - 部品ごとにクラスを書き換える：色は `brand-*`・`gray-*` の変数で当てているので、変数の値を差し替えるほうが、全画面に一度に効き、コントラストの関係も保てる
- **ルール**:
  - 色は `app/globals.css` の `html:has(.dl-admin)`（昼）と `html.dark:has(.dl-admin)`（夜）で、`brand-*` と `gray-*` の値を差し替えて当てる。部品のクラスは、役目（`brand-500` は主な塗り、`gray-500` は補足の文字など）をそのまま使う
    - 昼：`brand-500` は紺（主な塗り・リンク。白い文字と 12:1）、`brand-400` は濃い真鍮（線と小さな見出し。白の上で 5:1）、`brand-50`〜`300` は真鍮の淡い色（飾りと選択中の地）、`gray-50` は大理石の地、`gray-500`〜`900` は紺がかった文字の色
    - 夜：`gray-950`・`900`・`800`・`700` が濃紺の面（画面の地は `gray-950`、パネルは `gray-900`、入力欄・ホバー・選択中のような持ち上げた面は `gray-800`、さらに強い面は `gray-700`）。パネルから上の隣どうしの段は 1.3:1 以上離す（選択中のタブ・ホバーした行・パネルの縁が見えるように。PR #1124 の UI/UX のレビューで、最初の値は 1.04〜1.09:1 しか離れていなかった）。`gray-50`・`200`・`300` が文字、`brand-400` は明るい真鍮（文字・リンク・塗り。パネルの上で 12:1）、`brand-500`・`600` は白い文字を載せる青い塗り
  - どの段も、DADS のときのコントラストを保つか上回る値にする（白・画面の地・夜の面に対して計算して確かめた）。値を変えるときは計算し直す
  - 引き継ぐ基準（DADS のときと同じ数字）：文字は背景と 4.5:1 以上、枠線・アイコンは 3:1 以上。補足の文字は `gray-500` より薄くしない。本文は 16px 以上（14px は補足だけ）。押せる範囲は 44px 以上。塗りのボタンは1画面に原則1つ。色だけで意味を伝えない
  - フォーカスは、黒の outline と Yellow の二重の枠のまま（昼も夜も、どの面の上でも見える）。部品ごとに色を変えない
  - 夜の主なボタンは真鍮の塗りに紺の文字（`components/ui/button.tsx`）。夜に `brand-400` を塗りに使うときは、文字を `gray-900` にする（白い文字は載せない）
  - カードは上に真鍮の線を持つ（`components/ui/card.tsx`）。影は重なって出る部品だけ、という決まりは変えない。カードに `dark:border-*` を渡すと夜の真鍮の線が消えるので渡さない。意味を色で示す線（`decoration`）は、昼も夜も同じ意味の色を出す
  - リンクは常に下線を引く（昼の紺は本文の紺と近く、色だけでは見分けられない）。`hover:underline` だけのリンクを足さない
  - 青・紫を直接書かない所：リンク（`text-brand-500 underline underline-offset-2 hover:text-brand-600 dark:text-brand-400 dark:hover:text-brand-300`）、選択中の印と帯、行のホバー（昼は `hover:bg-brand-50`）、意味を持たない飾りのアイコン。夜の色を書いていない `text-blue-600` のリンクは、濃紺の上で読みにくかった。種類や意味を色で分けている所は、色を残す（バッジの色、`Callout` の種類、進捗バーの色の指定、ファネルの段、通知の種類のアイコン、顧客探しの列の地）。オーナーの答えが無いので案のとおりにした。変えるときは、種類が見分けられることを確かめる
  - 夜の「選択中」は真鍮でそろえる（枠 `dark:border-brand-400` と地 `dark:bg-brand-400/[0.14]`。メニューの選択中と同じ型）。夜に青の `brand-500`・`600` を選択中の印に使わない
  - 取り消せない操作のボタンは、夜も赤の塗りに白い文字にする。主なボタンのクラスに赤だけを足すと、夜は真鍮の塗りと紺の文字が残る（`dark:bg-red-*` と `dark:text-white` まで書くか、`variant="destructive"` を使う）
  - グラフの鍵の色（`key`）は昼 `#a8842f`・夜 `#e9cf9a`。真鍮は amber・yellow と同じグラフに並べない（見分けにくい）
  - メニューの部屋の名前は、機能の名前の下の行に 14px で添える（横に並べると機能の名前が切れる）
  - メニューのように昼も夜も夜の色で描く部分には、同じ要素に `dark` と `office-night` を付ける（`dark` が中の `dark:` のスタイルを有効にし、`office-night` が夜の色の変数を与える）
  - 装飾は枠（メニュー・題・パネルの上の線）に置く。表と入力欄の上に、グラデーション・発光・ぼかしを載せない。押せる要素を `clip-path` で切り抜かない（フォーカスの枠が切れる）
  - メニューの時計（`components/layout/OfficeClock.tsx`）は実際の時刻の昼と夜を添えるだけで、テーマは変えない。出社の画面（PR #1105）にも同じ計算（18時〜6時が夜）がある。両方が main に入ったら1つにまとめる
- **ほかの決定への影響**（どれも消さない）:
  - `2026-10-24-admin-dads`：置き換えた。基準の数字とフォーカスは、この決定のルールに引き継いだ
  - `2026-11-08-admin-dark-gray-400`：ダークで `gray-400` を `gray-300` と同じ値にする決まりは、夜の色の中でそのまま守っている（値は新しい色）
  - `2026-11-07-ui-audit-owner-decisions`：ダークモードの文字の色の3段階（主 `gray-50`・補足 `gray-200`・控えめ `gray-300`）は役目をそのまま使い、値を夜の色に変えた
  - `2026-11-12-ai-employees-office`：「装飾の決まりを外すのはオフィスの画面だけで、ほかの管理画面には広げない」は、オーナーの判断で変わった。全画面の出社のような強い装飾（ガラスのパネル・切った角）を管理画面に広げるかは、この決定のルール（装飾は枠に置く）の範囲で進める
  - `2026-11-01-ui-audit-skill`：スキル `ui-audit` は DADS を基準に「AI らしさ」を直す手順なので、新しい決まりに合わせて書き直す必要がある（Claude の設定の変更なので、公式ドキュメントで確かめてから。別の Issue）
- **オーナーの判断が要ること**（PR #1124 のレビューから。#1120 に残す）: 夜のフォーカスの枠（黒の線は濃紺の上で見えず、黄の線だけになる。並びを入れ替えるか）、ロゴの印の色、メニューを部屋ごとの見出しでまとめるか、種類を分けている青と紫（バッジ・通知の種類など）も替えるか、昼の入力欄の枠を濃くするか
- **まだやっていないこと**（#1120）: その部屋の AI社員の案内、画面ごとの細かい直し（色つきの飾りの線・アイコンの地など）、グラフの色、Storybook の見本と Claude Design 用のデザインシステムの作り直し、スキル `ui-audit` の書き直し
