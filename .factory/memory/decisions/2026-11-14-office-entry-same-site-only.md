### [Security] 外のサイトが始めた要求では、出社の画面を自分で開かせない（アドレスの印をプロキシで外す。取り消せない操作の確認は、キーだけでは通さない）（#1175）
- **日付**: 2026-11-14
- **きっかけ**: PR #1174（#1169、ロゴで出社の画面をフロアから開く）の `security-specialist` のレビューの指摘 S1。出社の画面は、アドレスの印（`?source=app`・`login`・`home`）で自分で開き、キーだけで操作に届く（`E` → `1` で採用・休止・復帰、`5` → `1` で次の行動を済みにする）。外のサイトが、ログイン中の人に文字を打たせながら新しいタブでこのアドレスを開くと、続きの打鍵が出社の画面に届く可能性がある（コードから組み立てた筋道。実際の打鍵の届き方は試していない）。今届く操作は元に戻せるものだけだが、#1170 で解雇（取り消せない）が選択肢に入る
- **決定**（オーナーの判断。2026-11-14、こちらの推奨に「進めてください」）:
  - **a**：外のサイトが始めたページの要求（`Sec-Fetch-Site: cross-site`）で、オフィスのページに印が付いていたら、プロキシで印を外したアドレスへ送り直す（`lib/middleware/office-entry.ts`）。オフィスは通常の表示で開く
  - **b**：取り消せない操作（解雇）の確認は、数字のキーの続け打ちでは通せない形にする（ボタンのクリックか、名前の入力）。#1170 で実装する
- **却下案**: 印で開いたときは、最初のポインター操作か一定の時間までキーを無視する（打ち続ける相手には効きにくい）
- **ルール**:
  - 出社の画面を自分で開く印を足すときは、同じキー（`source`）に載せる。プロキシは値を見ずにキーごと外すので、新しい印も守られる。別のキーにするなら、`office-entry.ts` も直す
  - 判定は、ルーターが実際に出すパスで行う（言語の接頭辞の有無・エスケープ・末尾のスラッシュ・大文字小文字をならしてから比べる）
  - 送り直しは、ログインへの誘導より先に行う（印が `callbackUrl` に入って、ログインのあとに戻ってこないように）。どちらの送り直しも、誰が頼んだかで答えが変わるので `Cache-Control: private, no-store`
  - `Sec-Fetch-Site` が `same-origin`（アプリの中の移動）・`none`（アドレスの入力・ブックマーク・インストールしたアプリの起動）・`same-site` のとき、ヘッダーが無いとき（古いブラウザ）は、今までどおり。古いブラウザでは守りが効かないので、取り消せない操作は b で別に守る
  - 出社の画面に、キーだけで届く取り消せない操作を足さない。足すなら、確認をキーだけで通せない形にする
- **確かめたこと**（2026-11-14、手元の開発サーバー）: 別のホストのページからのリンク（`source=home`・`source=login`）と `window.open` で、307 のあと通常の表示のオフィスが開き、出社の画面は開かない。続けて `e`・`1` を打っても何も起きない。ロゴ（同じオリジン）と、アプリの開始 URL を直接開いた場合は、今までどおり出社の画面が開く
- **確かめていないこと**: Safari・Firefox での `Sec-Fetch-Site` の付き方（Chromium だけで確かめた）。インストールしたアプリを実機で起動したときの値（仕様では `none`）
- **残る経路**: 外のサイトのリンクが、ログインの画面に `callbackUrl=/ja/office?source=home` を付けて開かせた場合、利用者がその場でログインすると、ログインのあとに出社の画面が開く（ログイン済みの人は、ログインの画面から自動では送られない）。利用者が自分でログインの操作をする必要があるので、今回は対象にしていない
