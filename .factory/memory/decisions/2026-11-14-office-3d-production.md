### [UI] AI社員オフィスの 3D を本実装に進める。全場面を 3D・ロボットはデザイナーの 3D モデル・本番の既定を 3D にする（Epic #1146）
- **日付**: 2026-11-14
- **決定**（オーナーの判断。2026-11-14「3D を本実装に進める」。進め方は、その場で4点を確かめた）:
  - 検証の PR #1136（three.js と React Three Fiber の依存）を main に入れる（同日マージ済み）
  - 3D にする範囲は、フロアだけでなく、**会話・部屋・カスタマイズも**
  - ロボットは、**デザイナーの 3D モデル**にする（こちらの推奨は「コードで組む立体のまま」だった）
  - 本番では、**既定を 3D** にする（こちらの推奨は「切り替え式・既定は 2D」だった）
- **理由**: オーナーが求めているのは、斬新な業務システムとしての没入感（決定 `2026-11-13-office-is-the-base`）。AI社員が部屋を移動する動きと感情を、どの場面でも、作り込んだ姿で見せる
- **判断にともなうリスクと、その受け方**:
  - 実機での描画の速さは測れていない（手元はソフトウェア描画で毎秒 7〜58 コマ）。既定を 3D にする前に、遅い端末と WebGL が使えない端末で 2D に戻す仕組みを入れ、実機で測ってしきい値を決める（#1150）
  - デザイナーの 3D モデルはまだ無い。誰が作るか・時期はオーナーが決める。仕様書・見本のファイル・読み込みの仕組みを先に用意し、届くまではコードで組んだロボットを使う（#1151）
  - 全場面を 3D にすると作る量が増える。フロア（#1147）→ 場面（#1148）→ 背景（#1149）→ 既定の切り替え（#1150）の順に、小さい PR で進める。既定の切り替えは、3D が 2D と同じに使えるようになってから
- **ルール**（`2026-11-13-office-3d-react-three-fiber` のルールに足す）:
  - 3D の絵は飾り（`aria-hidden`・ポインタを受けない）。押せるもの・読み上げるものは DOM に置く。フロアの名札は、2D と同じボタン（`WorldTagButton`）を 3D の上に重ね、キャンバスが毎コマ知らせる視点（`onView`）で置く（`office-tags-3d.tsx`）
  - キャンバスには `style={{ pointerEvents: 'none' }}` を渡す。React Three Fiber は外側の要素に `pointer-events: auto` を inline で付けるので、クラス（`pointer-events-none`）では消せず、床のドラッグとホイールが届かなくなる（#1147 でブラウザで見つけた。単体テストはキャンバスをモックするので気づけない）
  - 名札の層は、キャンバスが最後に知らせた視点を覚えておき、描き直しのたびに自分を置く（`lastShown`）。「動きを減らす」設定ではキャンバスが変化のときしか描かないので、次のコマを待つと名札が出ない
  - カメラと、床の場所が画面のどこに出るかは、純粋な関数（`office-view-3d.ts`）で決める。キャンバスのカメラも名札も、同じ関数を使う（ずれない・単体テストで固定できる）
  - 3D の側の変更は `office-3d/` に置き、入れ物（`office-immersive.tsx`）には、渡す値と重ねる層だけを足す
  - 2D の絵は消さない。失敗・遅い端末・利用者の選択のための控えとして残す
  - 「動きを減らす」設定では、歩かせず、浮き沈み・首振り・手振りも止め、変化があったときだけ描く
  - モデルの圧縮（Draco・meshopt・KTX2）は WASM を使うので使わない。本番の CSP を変える必要が出たら、`security-specialist` のレビューを通す
- **まだ決まっていないこと**: モデルを誰が作るか・役割ごとに別のモデルにするか・カスタマイズの項目をモデルでどこまで選べるようにするか（#1151）、遅い端末で 2D に戻すしきい値（#1150）、社長のアバター、音
