### [UI] AI社員オフィスの 3D を本実装に進める。全場面を 3D・ロボットはデザイナーの 3D モデル・本番の既定を 3D にする（Epic #1146）
- **日付**: 2026-11-14
- **決定**（オーナーの判断。2026-11-14「3D を本実装に進める」。進め方は、その場で4点を確かめた）:
  - 検証の PR #1136（three.js と React Three Fiber の依存）を main に入れる（同日マージ済み）
  - 3D にする範囲は、フロアだけでなく、**会話・部屋・カスタマイズも**
  - ロボットは、**デザイナーの 3D モデル**にする（こちらの推奨は「コードで組む立体のまま」だった）
  - 本番では、**既定を 3D** にする（こちらの推奨は「切り替え式・既定は 2D」だった）
- **理由**: オーナーが求めているのは、斬新な業務システムとしての没入感（決定 `2026-11-13-office-is-the-base`）。AI社員が部屋を移動する動きと感情を、どの場面でも、作り込んだ姿で見せる
- **判断にともなうリスクと、その受け方**:
  - 実機での描画の速さは測れていない（手元はソフトウェア描画で毎秒 7〜58 コマ）。既定を 3D にする前に、遅い端末と WebGL が使えない端末で 2D に戻す仕組みを入れ、実機で測ってしきい値を決める（#1150）
  - デザイナーの 3D モデルはまだ無い。誰が作るか・時期はオーナーが決める。仕様書・見本のファイル・読み込みの仕組みを先に用意し、届くまではコードで組んだロボットを使う（#1151）
  - 全場面を 3D にすると作る量が増える。フロア（#1147）→ 場面（#1148）→ 背景（#1149）→ 既定の切り替え（#1150）の順に、小さい PR で進める。既定の切り替えは、3D が 2D と同じに使えるようになってから
- **ルール**（`2026-11-13-office-3d-react-three-fiber` のルールに足す）:
  - 3D の絵は飾り（`aria-hidden`・ポインタを受けない）。押せるもの・読み上げるものは DOM に置く。フロアの名札は、2D と同じボタン（`WorldTagButton`）を 3D の上に重ね、キャンバスが毎コマ知らせる視点（`onView`）で置く（`office-tags-3d.tsx`）
  - キャンバスには `style={{ pointerEvents: 'none' }}` を渡す。React Three Fiber は外側の要素に `pointer-events: auto` を inline で付けるので、クラス（`pointer-events-none`）では消せず、床のドラッグとホイールが届かなくなる（#1147 でブラウザで見つけた。単体テストはキャンバスをモックするので気づけない）
  - 名札の層は、キャンバスが最後に知らせた視点を覚えておき、描き直しのたびに自分を置く（`lastShown`）。「動きを減らす」設定ではキャンバスが変化のときしか描かないので、次のコマを待つと名札が出ない
  - カメラと、床の場所が画面のどこに出るかは、純粋な関数（`office-view-3d.ts`）で決める。キャンバスのカメラも名札も、同じ関数を使う（ずれない・単体テストで固定できる）
  - 3D の側の変更は `office-3d/` に置き、入れ物（`office-immersive.tsx`）には、渡す値と重ねる層だけを足す
  - 2D の絵は消さない。失敗・遅い端末・利用者の選択のための控えとして残す
  - 毎秒のコマ数は、出社の画面（`office-immersive.tsx`）の state にしない。キャンバスは `office-3d/office-fps.ts` のメーターの `report` に渡し、表示する部品だけが `useFps` で読む。state にすると、毎秒、入れ物全体（2D の絵・名札・3D の props）が描き直される（#1270）。遅い端末の判定（#1150）も、`onFps` の中でメーターと一緒に呼ぶ
  - 「動きを減らす」設定では、歩かせず、浮き沈み・首振り・手振りも止め、変化があったときだけ描く
  - モデルの圧縮（Draco・meshopt・KTX2）は WASM を使うので使わない。本番の CSP を変える必要が出たら、`security-specialist` のレビューを通す
- **そのあと決まったこと**（2026-11-14、オーナー。#1157）: #1150 の前に、本番の出社の画面にも 2D と 3D の切り替え（操作のバーのボタンと V キー）を出す。既定は 2D のまま・表示は覚えない。3D の間は、操作のバーの下に毎秒のコマ数を出し、オーナーが実機で測る（測った数字で #1150 のしきい値を決める）。状態と出来事を仮に変える検証用のパネルは、開発時だけのまま（`OFFICE_3D_TRIAL`）。決定 `2026-11-13-office-3d-react-three-fiber` の「切り替えは開発時だけ」は、これで置き換わる
- **そのあと決まったこと**（2026-11-14、オーナー。今の 2D のオフィスの画面を示して「3D でも最低限この世界観は目指す」「もっとリアルなバーチャルオフィスを再現したい」）:
  - **最低ライン**: 3D のフロアに、2D の絵にある物が全部ある（窓と外の街・木の壁とモニター・机とモニターと椅子・植物・ソファと応接・会議の机・サーバー・カウンター・吊り照明・ガラスの間仕切り・充電の台・受付）。配置は 2D と同じ。これを満たすまで、3D を既定にしない
  - **その上**: 2D の絵より本物らしくする。まずコードだけでできる所（素材の質感・窓から入る光と影・夜の照明・映り込み）を #1149 で入れた。家具やロボットを 3D モデルに置き換える所は #1151 の仕様に沿って進める
- **ルール**（#1149 で足した）:
  - 物の配置（窓・間仕切りと扉・机・椅子・植物・照明・丸い机・サーバー）は `office-furniture.ts` に置き、2D の絵（`office-scene.ts`）・3D の背景（`office-3d/office-scenery-3d.ts`）・歩く道筋（`office-3d/office-nav.ts`）が同じものを読む。1つしかない家具（ソファ・カウンター・棚・会議の机）は、置き場所の四角だけを共有し、細かい形はそれぞれの絵で組む。`office-scene.ts` の数字を変えたら `office-furniture.ts` も合わせる
  - 3D の背景は、箱・円柱・球の部品の一覧（純粋なデータ。単体テストで数と範囲を確かめる）にして、形と質感ごとに1回で描く（`InstancedMesh`）。物を足しても描く回数は増えない
  - 床の木目・大理石・窓の外の街・壁のモニターの絵は、ブラウザの中でキャンバスに描いて貼る（`office-textures-3d.ts`）。画像のファイルを足さない・外から読まない（CSP を変えない）。映り込みも three.js の `RoomEnvironment` をその場で作る
  - 夜の明かりは、照明ごとに光源を置かない。照明の下の「光だまり」（床に重ねる絵）と、部屋ごとの光源（6個まで）にする（光源は、全部の面の計算に効く）
  - 歩く道筋は、床を 0.1 の升目にして、家具・間仕切り・床の端から 0.18 以内を通れない升にし、最短の道（A*）を真っすぐにならす。扉は間仕切りの切れ目。椅子は、座っている本人だけが通れる。家具を足したら `OBSTACLES` に入れる（入れないと、ロボットが通り抜ける）
- **ルール**（#1148 で足した）:
  - 3D は、フロアだけでなく、会話・部屋・カスタマイズの場面の後ろにも出したままにする（タイトルの画面だけ 2D）。場面ごとのカメラ（どこを・どの近さで・画面のどこに）は純粋な関数 `stageView`（`office-view-3d.ts`）で決め、入れ物（`office-immersive.tsx`）は場面と対象の場所を渡すだけにする。画面のどこに置くかは 2D と同じ割合（会話とカスタマイズは左から 32%・上から 42%、部屋は左から 15%・上から 30%）
  - 場面が変わったときだけ、視点全体（見る場所・近さ・ずらし）を 0.9 秒かけて滑らせる。フロアでのドラッグと拡大は、今までどおりすぐ効かせる。「動きを減らす」設定では滑らせない
  - 名札（押せるボタン）はフロアの場面だけに出す。会話の相手は、こちらを向かせる（飾り。相手が誰かはパネルが伝える）
- **ルール**（#1148 の後半で足した。2026-11-15）:
  - カスタマイズのプレビューは、3D のときはフロアのロボットそのものにする。絵（2D）の場所を「窓」（何も描かない枠）にして、カメラがその窓の中にロボット全体を収める（`openingView`。`office-view-3d.ts`）。窓の場所は、置いた部品（`office-studio.tsx`）が画面で測って知らせる。割合で決め打ちしない（画面の幅と高さで、左のパネルの高さが変わる）
  - 下書きの見た目は、保存の前にフロアのロボットへ渡す（`onLook`）。カスタマイズを出たら外す（保存したものだけがフロアに残る）。下書きは自分の画面だけで、サーバーには送らない
  - 3D が出ていない間（2D・読み込み中・表示できなかったあと）は、今までの 2D の絵のまま。窓を出すのは、3D のフロアが最初の1コマを描いたあとだけ
  - 窓の中には、フロアにあるもの（机・ほかの AI社員）もそのまま映る。プレビュー用に別の 3D を作らない（3D の描画を2つ持たない。フロアとの続きが切れる）。隣の席が端に残る近さまで寄り（`OPENING_SUBJECT`・`OPENING_FILL`）、窓の縁を暗くして、まわりを引かせる。窓に収める大きさ（`OPENING_SUBJECT`）は 3D のロボットの大きさ（`ROBOT_SCALE`。`robot-3d.tsx`）に合わせた数字なので、ロボットの大きさを変えたら一緒に直す（#1159 でロボットが 1.25 倍になったとき、窓からはみ出す寸前だった）
  - カスタマイズの間、その AI社員は「社長が近づいた」ときの表情にする（目が開く・頭の上の印なし）。喜んでいる間の目は、どの目を選んでも同じ弧になり、選んだ目を確かめられない（`ui-ux-specialist` のレビューの指摘）。休止中（目を閉じ、色が暗い）と要確認は、状態どおりのまま（2D の絵と同じ）。休止中をカスタマイズの間だけ起きた姿で見せる案は、オーナーの判断（2026-11-15、選択肢から「今のまま」）で採らない。見た目を確かめたいときは、呼び戻してからカスタマイズする
  - 歩いている途中でも、窓にはその AI社員を映す（行き先ではなく、今いる場所を見る）
  - カードの文（話し方の見本・メッセージ）は2行分の高さを取っておく。行が増えて窓が低くなると、中のロボットが跳ねる
  - 縦に並ぶ幅（1024px 未満）では、窓は 2D の絵と同じ高さ・左の列と同じ幅までにし、暗幕は一様の薄い色にする（横のグラデーションは、窓が左にある広い画面だけ）
  - 出来事（`office-recent-events.ts`）は、サーバーが成功を返した採用と呼び戻しだけを記録する。休止は出来事にしない（状態どおり眠る）。名前の変更と解雇は出来事にしない。見せる時間は 8 秒で、歩いている間は数えない（席に着いてから数える。廊下で誰にも見られずに終わらない）
  - 検証用のパネル（開発だけ）の出来事は、実際の出来事より優先する
- **ルール**（#1177 で足した。オーナーの指摘「文字が被ってみえない部分も修正してください」）:
  - フロアの名札と部屋名は、2D でも 3D でも同じ DOM の層（`office-floor-labels.tsx`）に置く。2D の絵（SVG）の中に部屋名を描かない（HUD を避けられず、拡大で文字の大きさが変わる）
  - 置き場所は純粋な関数（`office-label-layout.ts`）で決める。名札は、ほかの名札と重なるときに上下にだけ動かす（選んでいる名札は動かさない）。部屋名は、HUD のパネル・ロボット・名札・ほかの部屋名・画面の端を避け、候補の場所（部屋の奥の上 → 床の中央 → 手前）の近くに空きが無ければ出さない
  - HUD の四角は、出社の画面の層の子要素を測って得る（画面を覆う子は床か幕なので除き、横幅いっぱいの子はその中身を使う）。パネルを足しても、印を付けなくてよい
  - 名札の層は自分の重なりの順（`isolate`）を持つ。選んでいる名札はほかの名札より手前、パネルよりは奥
- **ルール**（#1183 で足した。オーナーの指示「#1183 も続けて対応してください」）:
  - 出社の画面を開いたときの寄り具合は、左右のパネルの間の幅で決める（`homeCloseUp`。`office-president.ts`）。間が広いときだけ、今までの 1.2 倍まで寄る。狭いとき（幅 1680px くらいまで）は、フロア全体が見える大きさで始める（隅の研修室が社員名簿の下に入らない）。会話・部屋・カスタマイズの寄り具合は、画面によらず今までどおり。左右のパネルの幅（`HUD_SIDES`）を変えたら、この数字も合わせる
  - 床は、左右のパネルの間の中央に置く（`homeShift`。2D と 3D で同じ）
  - 名札は、パネルの下に入るときに、上下か横へ 80px まで動かして外に出す。届かないときは、ロボットと一緒にパネルの下に残す
  - 選んでいる社員は、頭の上の印（名札と同じ DOM の層）で示す。絵（SVG・3D）の中には描かない（名札が足元に下がるので、足元の輪は隠れる）
  - 操作のバーは3つのまとまり（社員・視点・出る）。キーは変えない
  - 3D の「研修中」の印は、2D と同じ角帽の絵にする（「…」は待っているように読める）
  - ミニマップ（左上の丸い地図）は外した（オーナーの判断。2026-11-14、こちらの推奨に「進めてください」）。居場所は社員名簿と名札で分かり、幅 1440px 前後では研修室の上に重なっていた
  - 見送ったもの：毎秒のコマ数（#1150 でしきい値が決まったら外す）
- **ルール**（#1159 の一部と #1234 で足した。オーナーの指示「次の指示の候補を全て対応してください」、2026-11-15）:
  - 3D のロボットは、モデルが届くまでの当面の形として、コードのまま 2D の見た目に寄せる：角の丸い頭・大きいバイザーと目・胸の役割の印（2D と同じ4つ）・艶のある殻・2D と同じ背の高さ（`ROBOT_SCALE`）。**モデルの入手先（#1151・#1159）は、オーナーの判断のまま**で、これは決めていない
  - 見せるのは実際の状態だけ：作業中は机のキーボードに手を伸ばす、研修中は角帽をかぶる（気分ではなく状態で決める。話しかけている間も外さない）。「動きを減らす」設定では、姿勢だけ残して動かさない
  - フロア案内は、左右のパネルの間（`HUD_SIDES`）に置く。幅が足りないときは、場所ごとの仕事の説明と部屋の印を画面から隠し（読み上げには残す）、それでも足りなければパネルの間で折り返す
  - 画面の幅いっぱいの入れ物（操作のバーとフロア案内を中央に寄せる行）は、ポインターを通す（`pointer-events-none`）。通さないと、下にある社員名簿の行が押せない
  - 描画の量の目安（手元のソフトウェア描画、会話の場面の1コマ）：ロボットを直す前は描画 126 回・三角形 78,594、直したあとは 133 回・83,464。実機の速さは測っていない
- **そのあと決まったこと**（2026-11-16、オーナー「暫定の毎秒20コマで進めてください」。#1150）:
  - 本番の出社の画面は、幅 768px 以上で **3D から始める**（`office-3d/office-display.ts` の `DEFAULT_DISPLAY`。この定数1つで戻せる）。上の「既定は 2D のまま・表示は覚えない」（#1157）は、これで置き換わる
  - **しきい値は暫定で毎秒 20 コマ**（`SLOW_FPS`）。実機の計測は、オーナーの画面の毎秒 60 コマ（2026-11-14 のスクリーンショット）の1件だけ。非力なノート PC・スマホの横向き・タブレットの数字が出たら見直す。計測のための毎秒のコマ数の表示は残す（#1183 の「しきい値が決まったら外す」は、暫定の間は保留）
- **ルール**（#1150 で足した）:
  - コマ数は、入れ物の state に置かない（#1270 の `office-3d/office-fps.ts`）。キャンバスからの報告は、コマ数の入れ物に渡してから、遅さの判定に渡す（`onFps3d`）
  - 最初の表示・覚える内容・遅さの判定は、純粋な関数（`office-display.ts`）と1つのフック（`use-office-display.ts`）に置く。入れ物（`office-immersive.tsx`）は、3D を出す・片付けるだけ
  - 覚えるのは端末ごと（`localStorage`。描画の速さは端末のもの）。覚えるのは「利用者が選んだ」と「遅くて 2D に戻した」だけで、読み込みの失敗・描画のエラー・WebGL が無いことは覚えない（次に開いたら、また試す）
  - 遅さの判定は1回だけ：3D が出てから最初の3回の報告（1秒に1回）は数えず、次の5回の平均がしきい値を下回ったら 2D に戻して伝え、次回は 2D から始める。**理由の文は、戻した回だけ出す**（オーナーの判断、2026-11-16「推奨どおり変えて」。毎日開く画面で、同じ文を毎回出さない）。次回からの 2D と、WebGL が無いブラウザの 2D は、何も言わずに始める（「3D 表示」を押して表示できなければ、そのとき伝える）。画面が隠れている間と「動きを減らす」設定の間は数えない。**利用者が自分で 3D を選んだら、その出社でも次の出社でも、自動では戻さない**
  - WebGL が使えるかは、3D のチャンクを読む前に確かめる（使えないブラウザに three.js を読ませない）。ブラウザが WebGL を知らないとき（単体テストの jsdom も）は、キャンバスにコンテキストを頼まない。単体テストは、この確認で three.js を読みに行かない
  - 本番ビルドの E2E（`csp.spec.ts` の管理画面のテスト）で、出社して canvas が出ること・ページのエラーと CSP 違反が無いことを確かめる。起動オプションは学び「ヘッドレスの Chromium で WebGL の画面と…」。ソフトウェア描画は遅く、数秒後に 2D に戻りうるので、最初のコマまでしか見ない
