### [Process] 認証・セキュリティ・課金に関わる PR は、マージ前に読み取り専用のレビューを通す
- **日付**: 2026-10-19
- **決定**: 次のどれかに当たる PR は、マージ前に読み取り専用のレビューを1回通す。それ以外は任意
  - 認証・認可：ログイン、セッション、Cookie、権限の判定、管理画面への誘導（`lib/auth/`、`proxy.ts` など）
  - セキュリティ：CSP やセキュリティ関連のヘッダー、公開 API の入力チェック・回数制限・Turnstile、メールや画面へ出す値のエスケープ、シークレットの扱い、本番 DB の権限・RLS
  - 課金・コスト：Vercel や Supabase のプラン・容量に効く設定（`vercel.json` の cron やデプロイの設定など）、有料 API の呼び出し量
- **理由**: 複数のセッションが並行してマージするため、事故の影響が大きい変更だけは別の目で見る。文言や画面の調整まで毎回レビューを待つと、公開前の作業が遅れる
- **却下案**: すべての PR でレビュー必須（軽い変更まで待ちが出る）、レビューなし（認証の変更で実際に指摘が出て直している。#239、#243）
- **ルール**:
  - レビューするエージェントには、編集・コミット・push・PR へのコメントを禁じ、閲覧だけをさせる（汎用のエージェントは、頼み方が緩いとソースを書き換えることがある）。観点に合う `.claude/agents/` の専門エージェントがあれば使う
  - blocker がなければマージしてよい。should-fix は直してからマージするか、Issue に残す
  - PR の本文か会話に、レビューの結論（マージ可かどうか）を残す
