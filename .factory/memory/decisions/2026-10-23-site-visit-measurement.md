### [Analytics] [Security] 公開ページの訪問を自前で計測する（#412, Epic #411）
- **日付**: 2026-10-23
- **決定**: すべての公開ページ（AX サイト・診断ビルダーの診断・トップ・landing・旧診断フォーム。FAQ とブログは #413 で閉じた）の表示を、自前で `site_visits` に記録する。クッキーは使わず、IP アドレスと UA は保存しない。AX 診断の公開前に入れ、プライバシーポリシーに書いてから本番で有効にする（`SITE_VISITS_ENABLED=true`）。ポリシーが間に合わなければ公開を待つ。GA4 は公開から有効にし、ポリシーに書く（いずれもオーナー判断）
- **理由**: STUDIO のアナリティクスのように、訪問からリードまでをアプリの中で見たい。Vercel と GA4 の数字は、それぞれの管理画面にしかなく、診断やリードと突き合わせられない
- **ルール**:
  - 訪問者は「その日（日本時間）だけのソルト・組織・IP・UA」の SHA-256 で数える。ソルトは `site_visit_salts` に当日分だけ置き、次の日の最初の記録と毎日の処理で消す。日をまたいで同じ人を識別しない。期間の訪問者数は、日ごとの訪問者数の合計
  - 記録するのは、パス・ページの種類・参照元のホスト・utm_*（`@` を含む値は捨てる）・AX の `from`（許可した値だけ）・端末の種類・日付だけ。時刻、参照元の URL 全体、クエリのほかの値、UA、IP は残さない（時刻があると、同じ時刻の診断の回答と突き合わせられるため）
  - 存在しないページで記録を増やせないようにする: コラムは実在するものだけ、ビルダーの診断は公開中のものだけを数え、旧診断フォームはパスの後ろを捨てて1ページとして数える
  - 組織はページのパスからサーバーで決める。自社のページ（AX サイト・トップ・landing・旧診断フォーム）は運営の組織（`AX_DIAGNOSIS_ORGANIZATION_ID`、なければ `DEFAULT_ORGANIZATION_ID`）、ビルダーの診断はその診断の組織。ページから組織は受け取らない（2026-10-23 オーナー判断：自社のページは運営の組織にそろえる）
  - 画面でサイトの訪問を見られるのは、分析レポートと同じく、リードを読める人（親組織の閲覧者を除く）。集計だけを出し、`visitor_hash` は画面・API・CSV に出さない（2026-10-23 オーナー判断）
  - `/api/collect` は同じサイトからの送信（Origin が一致）だけを受け、ボットと計測しないページ、4KB を超える本文は捨て、いつも 204 を返す。回数制限は「当日のソルトと IP の範囲（IPv6 は /64）」のハッシュで数える（10 分に 120 件。UA を変えても抜けられない）。信頼できる IP がないとき（Vercel 以外）は回数制限をかけない
  - 読み取り専用の DB ユーザー（`dl_readonly`）からは `site_visit_salts` を読めなくする（その日のうちにソルトとハッシュを並べて IP を総当たりされないため。本番の SQL で REVOKE）
  - 生の記録は 90 日で消し、日ごとの集計（`site_visit_daily`）は残す。集計は1つの SQL 文で、直近2日と消す直前の日を数え直す。毎日の処理は Webhook の定期実行に相乗りし（プランが毎日の実行しか許さないかもしれないため）、回数制限の古い枠の掃除もここで行う
  - 管理画面・ログイン・トークンを持つページ（配信停止・確認）、AX 診断へ転送される旧診断フォームのテンプレートのページは計測しない
- **未決**: 生の記録の保存期間（90日は案。法務の確認待ち）、日ごとのハッシュ値が個人関連情報に当たるか（経営管理部・法務）、Vercel のリクエストログと Supabase のバックアップに残る IP・ソルトをポリシーでどう書くか
