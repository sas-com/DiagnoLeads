### [Sales] 商談を持つリードの状態と商談フェーズは商談から毎回計算し、手では変えない（#444）
- **日付**: 2026-10-25
- **決定**: 商談を1件以上持つリードの状態と商談フェーズは、商談の作成・変更・削除のたびに商談から計算し直す。`leads.update`・一括の状態変更・REST API v2 の PATCH では、商談を持つリードの状態と商談フェーズを変えられない。決定 `2026-10-24-deals-beside-leads` の「前に進む向きだけにする（成約のリードは成約のまま、フェーズは戻さない）。商談を削除してもリードは変えない」をこれで置き換える（ほかのルールはそのまま）。営業パイプラインの評価（Epic #430）の推奨案。オーナーは「推奨プランで進めて」「このセッションの担当を完了させて」と指示（2026-10-24・25）
- **理由**: 状態・商談フェーズを手でも商談からも書けると、商談と食い違う。前に進めるだけだと、受注を開き直したとき・商談を消したときにリードが戻らず、集計（ダッシュボード・ファネル・代行のファネル）が商談とずれる
- **ルール**:
  - 状態：受注の商談があれば成約（次の商談が開いていても成約のまま）、なければ開いた商談があれば商談中、すべて失注なら失注
  - 商談フェーズ：商談の示すいちばん先のフェーズ（受注を開き直す・消すと戻る）。どの商談もフェーズを示さない（すべて失注、保守・運用だけの受注など）ときは、リードのフェーズを変えない。各フェーズに初めて入った日は残す
  - 商談済みの印は一度付いたら消さない。失注の理由は、商談中に戻っても残す（切り返しカードが読む）
  - 最後の商談を消したら、リードはそのままの値で残り、手で変えられるようになる
  - 再育成：商談を持つリードはナーチャリングにしない。止まった商談は、失注の理由「時期」で閉じる。リードは時期の失注になり、動くべき時期（#151）が再接触を追う。時期が来たら新しい商談を作る
  - 拒むのは値が変わるときだけ。フォームが今の値をそのまま送る保存（名前の修正など）は通す。tRPC は BAD_REQUEST（`DEAL_DRIVEN_MESSAGE`）、REST API v2 は 409。一括の状態変更は商談のあるリードを外して残りを変え、外した件数（`skippedWithDeals`）を返す
  - 画面：`leads.get`・`leads.list` が `hasDeals` を返す。状態・商談フェーズのバッジは、商談のあるリードでは選べない（「商談から反映」）。パイプラインのカードの商談フェーズも同じ
  - ロック：商談の削除も、リード → 商談の順にロックする（作成・変更と同じ）
- **見直しの条件**: 商談を持つリードを止めたまま育成したい運用（時期の失注では足りない）が出たら、商談に「保留」の扱いを足すかを決める
- **却下案**: 商談がすべて時期の失注ならリードをナーチャリングにする（動くべき時期はすでに時期の失注を追うので、状態を増やすと集計と通知の意味が二重になる）
