### [UX] 管理画面の利用ガイドは、コードに型付きの記事で置き、画面を変える PR で一緒に直す（Epic #877）
- **日付**: 2026-10-28
- **決定**: オーナーの依頼「サービス利用ガイドを管理者サイトに組み込み、別途マニュアルが無くても利用できるサービスにする」に対し、オーナーが4点とも推奨案で判断した
  - 置き場所：ガイドの本文はコードに型付きの記事で置く（`lib/features/help/`。AX コラムと同じ方式で、Markdown や HTML は使わない）。画面を変える PR で、その画面の記事も一緒に直す
  - 範囲：4つの層をすべて作る。①画面ごとの「この画面の使い方」（#872・#873）、②項目の説明（Epic #780 の残りで進め、#877 では重ねない）、③ヘルプセンター `/help`（目次・検索・用語集・業務の流れ、#874）、④役割ごとの初回のチェックリスト（#875）
  - 読者：当面は社内（エス・エー・エス）だけ。営業代行など社外のアカウント（#276）を作るときに足す
  - 言語：日本語から。英語の画面でも日本語の記事を出し、英語版は必要になったら足す
- **理由**: 既存の `docs/USER_GUIDE.md` は 2025年頃のもので、今の画面とほぼ合っていなかった（存在しない画面・古い状態の名前）。画面と別の場所に置いた文書は、画面の変更に置いていかれる。CMS（Payload）は本番で止まっていて記事を持てず、DB に置くと編集画面・権限・セキュリティレビューが先に要る
- **却下案**:
  - DB に置いて編集画面を作る（デプロイせずに直せるが、画面の変更と記事がずれやすい。編集者の判定の仕組みもまだない）
  - CMS を有効にして使う（本番での有効化と P2・P12 が先に要り、時間がかかる）
  - `locales/` に置く（管理画面はカタログを丸ごとクライアントに渡すので、長文で重くなる。衝突しやすいファイルでもある）
- **ルール**:
  - 管理画面のすべてのページ（`app/[locale]/(dashboard)/**/page.tsx`）は、記事の `routes` に入るか、`HELP_EXCLUDED_ROUTES` に理由つきで入る。`test/unit/features/help/registry.test.ts` が検査する。ページを足す・名前を変える PR は記事も足す（`.claude/rules/help.md`）
  - 記事のリンクは管理画面のパス（ロケールなし）か `/help/<id>` だけ。外のサイトへは張らない（ヘルプは画面の中で完結させる）
  - リポジトリは公開。社外秘（取引先名・単価・営業の手引きの本文）は書かない。組織ごとの業務の手順は、営業の手引き（DB、決定 `2026-10-15-sales-playbook-in-db`）に置く
  - 記事の `reviewedAt` は、その記事を今の画面と突き合わせた日にする
  - 見た目は DADS（決定 `2026-10-24-admin-dads`）に従う
