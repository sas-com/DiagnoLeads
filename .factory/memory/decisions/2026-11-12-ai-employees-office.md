### [Architecture] AI社員は組織が採用して自律で働く担当者として新設し、オフィスの間取りの画面で見せる（Epic #1100）
- **日付**: 2026-11-12
- **決定**（オーナー判断）: 「AI社員オフィス」は、既存の AI・自動処理を社員に見立てて見せるだけの画面ではなく、組織ごとに採用でき、決まった仕事を自律して行う AI社員を新しく作る。働きぶりは `/office` のバーチャルオフィスの画面（フロアの地図・状態・作業記録）で見せる。Epic #1100 と子 Issue（#1101 土台、#1102 実行の基盤、#1103 AI評価担当）に分けて段階的に進める
- **理由**: オーナーが3案（既存機能の可視化・自律型の新設・画面だけ先に）から自律型を選んだ
- **却下案**:
  - 既存の AI・自動処理を社員として見せるだけ：スキーマ変更なしで小さく出せるが、オーナーが選ばなかった
  - 画面の器だけ固定のデータで先に作る：中身のない画面が本番に出る
- **ルール**:
  - 役割は会社の部門にする（オーナーの判断、2026-11-12）：マーケター・セールス・エンジニア・バックオフィス。利用者は社長として AI社員に指示を出す、という世界観に合わせる。価値が渡る順（見込み客 → 商談 → 提案 → 受注）に並べる。最初の3役割（追客担当・評価担当・時期の見張り番）は、仕事の中身をそのままにセールス・マーケター・バックオフィスに引き継ぎ、エンジニアを新設した（仕事は #1110）。席は営業フロア・マーケティング室・開発室・総務・受付（バックオフィスは受付カウンターの中）
  - 役割はコードのカタログ（`lib/features/ai-employees/types/roles.ts`）で決め、1つの組織に1つの役割につき1人（`ai_employees` の一意の索引）。DB には採用したことだけを置く
  - 役割の仕事がまだ載っていない間は、仕事のカタログ（`lib/features/ai-employees/types/works.ts`）の `issue` に Issue の番号を書き、画面では「研修中」として働かせない。仕事を載せる PR で `null` にする（役割の定義の `workIssue` は、決定 `2026-11-13-ai-employee-agents-work-packs` で仕事のカタログに移した）
  - 作業記録（`ai_employee_runs`）には件数と結果のコードだけを書き、リード・個人・プロンプト・自由な文を書かない（組織の全員が見るため）。結果のコードは DB の CHECK で `^[a-z_]{1,40}$` に限る（エラー文にはリードの値が入りうるため。PR #1105 のセキュリティのレビュー）
  - 解雇しても作業記録は消さない。作業記録に役割（`role`）を持たせ、`employee_id` は解雇で NULL にする（`ON DELETE SET NULL`）。誤動作に気づいて解雇したあとも「いつ・何件動いたか」を追えるようにするため（PR #1105 のアーキテクチャのレビュー）
  - AI社員の実行は、待機も複数のステップもない1回で終わるまとめ処理なので、ワークフローのランナー（`flow_runs`、決定 `2026-10-24-workflow-runner-self-built`）には載せず、`ai_employee_runs` に置く（ランナーの決定のルール「`after()` や既存の定期実行で足りる処理は載せ替えない」と同じ扱い）。#301 の滞留の検知ができたら、共有するかを決め直す
  - 見る権限は `read Analytics`（メンバーと親組織の閲覧者も見られる）、採用・名前の変更・休止・解雇は `update Settings`（管理者）。新しい CASL の対象は足さない
  - オフィスの画面は、オーナーの指示（2026-11-12）で、リアルなバーチャルオフィスにする。フロア全体を等角投影（アイソメトリック）で立体的に描き（奥の壁と窓・ガラスの間仕切り・家具・床の影。`components/features/ai-employees/office-scene.ts`）、AI社員をロボットの姿で置き、状態に合わせて居場所を変える（作業中・要確認は自分の席、待機中はラウンジ、研修中は研修室、休止中は充電ステーション。`office-map-layout.ts`）。ロボットの下の名札がボタン。デザインは Claude Design のキャンバスで作ってからコードに移した。地図の絵は特定の既存サービスに似せないオリジナルにする
  - デスクとロボットの向きを合わせる（オーナーの指示、2026-11-12）：席はデスクの奥（床の -y 側）に置き、座る者は +y を向く。キーボードは席の側、モニターは向こうの縁に置いて背を見る人に向ける。席の位置はデスクから導く（`office-map-layout.ts` の `ROLE_DESKS`・`seatOfDesk`）ので、机だけ・ロボットだけを動かしてずらさない。ラウンジ・研修室でも、ロボットは机かテーブルの方を向く（`facing`）
  - ロボットはオリジナルの造形「デスク・コンパニオン」にする（`office-robot.ts`）：浮いた台座と光の帯、卵形の胴と継ぎ目、役割の印を出す胸のパネル、関節のある腕、ガラスのバイザーと LED の目、耳のセンサー、状態を示すアンテナの灯り。役割ごとに色と装備を変えて見分けられるようにする（マーケター：紫・頭のスキャナーと片目のレンズとゲージ／セールス：青緑・ヘッドセットとチェックリスト／エンジニア：青・額のゴーグルとコードの印／バックオフィス：橙・ひさしと時計）。役割の色は状態の色（緑・赤・水色・黄・灰）と別にする。役割を足すときは、色・装備・胸の印を足す。既存の作品やサービスのロボットに似せない
  - ライトとダークは昼と夜を表す（オーナーの指示、2026-11-12）：ライトは昼（太陽と雲、窓の外の空と街並み、窓から床に差す日差し）、ダークは夜（星と月、灯りのついた夜景、ペンダントライトとその光だまり、窓からの月明かり）。夜は灯っていないものを暗くし、ランプ・画面・夜景は明るいまま残す。床の光は床の形で切り抜く。ペンダントライトは、ロボットがいる場所の手前（見る側）に吊らない（テストで確かめる）
  - 高級感のある素材にそろえる（オーナーの指示、2026-11-12）：ウォールナットの天板と黒いスチール脚のデスク、オークとウォールナットの床、大理石の廊下・受付・テーブル、真鍮の縁取り、黒枠の背の高い窓と黒い手すりのガラスの間仕切り、革の椅子、ベルベットのソファ、壁のウォールナットのパネルと額。家具を足すときはこの素材の範囲で選ぶ
  - この画面に限り、オーナーの指示（2026-11-12「デザインガイドを変えてでもリアルに」）で、決定 `2026-10-24-admin-dads` の「装飾を控える」（グラデーション・影・発光を使わない、影は重なる部品だけ）を外す。ほかの管理画面には広げない。それでも守ること：絵は `aria-hidden` にして状態は必ず文字とアイコンでも書く、名札の文字は背景と 4.5:1 以上、押せる範囲は 44px 以上（狭い画面）、動きは `motion-safe` の明滅だけ、ダークモード用に夜の絵を持つ
  - 全画面の「出社」（#1109、オーナーの指示 2026-11-12「業務アプリの概念を変える」「自分が社長になって AI社員に指示を出す世界観」）：通常の表示の「出社する（全画面）」から入り、タイトル → オフィス → 会話の3つの場面で進む（`office-immersive.tsx`。画面の案は Claude Design で先に作った）。利用者は社長で、AI社員に話しかけて指示を出す。守ること：
    - 画面に出すものは、すべてオフィスの実際の状態から作る（`office-president.ts`）。「社長の仕事」は要確認・休止中・空席から、会話の選択肢は状態と権限から決める。物語のための作りごとの数字・章・進み具合は出さない
    - 会話の文は決まった文面（`locales/*/aiOffice.json` の `immersive.talk.lines`）で、Claude に作らせない。生成に変えるときは、決定 `2026-10-24-ai-call-rate-limits` と `2026-10-25-ai-no-personal-data` に従って別の Issue で決める
    - 指示（採用・休止・再開）は既存の `aiEmployees.hire`・`update` を呼ぶだけで、権限は通常の表示と同じ（`update Settings`）。名前の変更・解雇・作業記録は通常の表示に残す
    - 出社の中の昼と夜は、テーマではなく実際の時刻で決める（18時〜6時が夜）。時刻は画面に出す時計と同じタイムゾーン（next-intl の設定）で読む。通常の表示はライト＝昼・ダーク＝夜のまま
    - 社員名簿は価値が渡る順に並べ、各部門の役目（見込み客を見つける → 商談にする → 提案をつくる → 期限を守る）を添える
    - 広い画面（1280px 以上）では、パネルを床のひし形の外の四隅に置き、フロア全体が見える位置からカメラを始める（`homeView`）。部屋の名前は床の外（奥の壁の上・手前の縁の下）に出し、ロボットと名札に重ねない。会話の場面では部屋の名前を出さない
    - 全画面の層は `role="dialog"` で、Esc は1つずつ戻る（会話 → オフィス → タイトル → 通常の表示）。キーボードだけで操作できる（Enter・E・数字キー・Tab）。動きは `motion-reduce` で止める
    - まだ無いもの：状態が変わったときにロボットが歩く動き、データをオフィスの物として置くこと、3D。#1109 の続きで扱う
  - Claude を呼ぶ役割（評価担当）は、決定 `2026-10-24-ai-call-rate-limits` と `2026-10-25-ai-no-personal-data` に従い、マージ前に `security-specialist` のレビューを通す（#1103）
