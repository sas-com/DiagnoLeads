### [Architecture] AI社員は組織が採用して自律で働く担当者として新設し、オフィスの間取りの画面で見せる（Epic #1100）
- **日付**: 2026-11-12
- **決定**（オーナー判断）: 「AI社員オフィス」は、既存の AI・自動処理を社員に見立てて見せるだけの画面ではなく、組織ごとに採用でき、決まった仕事を自律して行う AI社員を新しく作る。働きぶりは `/office` のバーチャルオフィスの画面（フロアの地図・状態・作業記録）で見せる。Epic #1100 と子 Issue（#1101 土台、#1102 実行の基盤、#1103 AI評価担当）に分けて段階的に進める
- **理由**: オーナーが3案（既存機能の可視化・自律型の新設・画面だけ先に）から自律型を選んだ
- **却下案**:
  - 既存の AI・自動処理を社員として見せるだけ：スキーマ変更なしで小さく出せるが、オーナーが選ばなかった
  - 画面の器だけ固定のデータで先に作る：中身のない画面が本番に出る
- **ルール**:
  - 役割はコードのカタログ（`lib/features/ai-employees/types/roles.ts`）で決め、1つの組織に1つの役割につき1人（`ai_employees` の一意の索引）。DB には採用したことだけを置く
  - 役割の仕事がまだ載っていない間は `workIssue` に Issue の番号を書き、画面では「研修中」として働かせない。仕事を載せる PR で `null` にする
  - 作業記録（`ai_employee_runs`）には件数と結果のコードだけを書き、リード・個人・プロンプト・自由な文を書かない（組織の全員が見るため）。結果のコードは DB の CHECK で `^[a-z_]{1,40}$` に限る（エラー文にはリードの値が入りうるため。PR #1105 のセキュリティのレビュー）
  - 解雇しても作業記録は消さない。作業記録に役割（`role`）を持たせ、`employee_id` は解雇で NULL にする（`ON DELETE SET NULL`）。誤動作に気づいて解雇したあとも「いつ・何件動いたか」を追えるようにするため（PR #1105 のアーキテクチャのレビュー）
  - AI社員の実行は、待機も複数のステップもない1回で終わるまとめ処理なので、ワークフローのランナー（`flow_runs`、決定 `2026-10-24-workflow-runner-self-built`）には載せず、`ai_employee_runs` に置く（ランナーの決定のルール「`after()` や既存の定期実行で足りる処理は載せ替えない」と同じ扱い）。#301 の滞留の検知ができたら、共有するかを決め直す
  - 見る権限は `read Analytics`（メンバーと親組織の閲覧者も見られる）、採用・名前の変更・休止・解雇は `update Settings`（管理者）。新しい CASL の対象は足さない
  - オフィスの画面は、オーナーの指示（2026-11-12）で、リアルなバーチャルオフィスにする。フロア全体を等角投影（アイソメトリック）で立体的に描き（奥の壁と窓・ガラスの間仕切り・家具・床の影。`components/features/ai-employees/office-scene.ts`）、AI社員をロボットの姿で置き、状態に合わせて居場所を変える（作業中・要確認は自分の席、待機中はラウンジ、研修中は研修室、休止中は充電ステーション。`office-map-layout.ts`）。ロボットの下の名札がボタン。デザインは Claude Design のキャンバスで作ってからコードに移した。地図の絵は特定の既存サービスに似せないオリジナルにする
  - デスクとロボットの向きを合わせる（オーナーの指示、2026-11-12）：席はデスクの奥（床の -y 側）に置き、座る者は +y を向く。キーボードは席の側、モニターは向こうの縁に置いて背を見る人に向ける。席の位置はデスクから導く（`office-map-layout.ts` の `ROLE_DESKS`・`seatOfDesk`）ので、机だけ・ロボットだけを動かしてずらさない。ラウンジ・研修室でも、ロボットは机かテーブルの方を向く（`facing`）
  - ロボットはオリジナルの造形「デスク・コンパニオン」にする（`office-robot.ts`）：浮いた台座と光の帯、卵形の胴と継ぎ目、役割の印を出す胸のパネル、関節のある腕、ガラスのバイザーと LED の目、耳のセンサー、状態を示すアンテナの灯り。役割ごとに色と装備を変えて見分けられるようにする（追客担当：青緑・ヘッドセットとチェックリスト／評価担当：紫・頭のスキャナーと片目のレンズとゲージ／時期の見張り番：橙・見張りの帽子と時計）。役割の色は状態の色（緑・赤・水色・黄・灰）と別にする。役割を足すときは、色・装備・胸の印を足す。既存の作品やサービスのロボットに似せない
  - この画面に限り、オーナーの指示（2026-11-12「デザインガイドを変えてでもリアルに」）で、決定 `2026-10-24-admin-dads` の「装飾を控える」（グラデーション・影・発光を使わない、影は重なる部品だけ）を外す。ほかの管理画面には広げない。それでも守ること：絵は `aria-hidden` にして状態は必ず文字とアイコンでも書く、名札の文字は背景と 4.5:1 以上、押せる範囲は 44px 以上（狭い画面）、動きは `motion-safe` の明滅だけ、ダークモード用に夜の絵を持つ
  - Claude を呼ぶ役割（評価担当）は、決定 `2026-10-24-ai-call-rate-limits` と `2026-10-25-ai-no-personal-data` に従い、マージ前に `security-specialist` のレビューを通す（#1103）
