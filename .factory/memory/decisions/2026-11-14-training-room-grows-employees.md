### [Architecture] 研修室を AI社員を育てる場所（オンボーディング・評価面談・昇格）にする。鍵6で入り、エージェントは Messages API と自前のループ・Claude Sonnet 5.5・等級は4段階で昇格は社長の承認（Epic #1187）
- **日付**: 2026-11-14
- **決定**（オーナーの判断。2026-11-14、このセッションで選択肢から選んでもらった。どれもこちらの推奨）:
  1. **研修室の役目**：AI社員を育てる場所にする。採用した AI社員のオンボーディング（自分の言葉で役割を報告し、社長が承認する）、毎月の評価面談、昇格の承認をここで行う
  2. **入り方**：数字のキー **6** を足す。フロア案内とフロアの札（部屋名）からも入れる
  3. **実行の基盤**（#1114 の決めること1）：Messages API ＋ 自前のループ。記憶と会話の記録は自社の DB に置く。Claude Managed Agents は使わない
  4. **モデル**（#1114 の決めること2）：Claude Sonnet 5.5（既存の AI 機能の `CLAUDE_MODEL` と同じ）
  5. **等級**（#1114 の決めること3）：4段階。研修中 → Lv.1 試用期間 → Lv.2 一人前 → Lv.3 主任 → Lv.4 エース。等級は任される範囲に結び付ける。昇格は、基準に届いたときに AI社員が推薦し、評価面談で社長が承認する。基準を下回ったら自動で範囲を絞る
  6. **時期**：オンボーディング・評価面談・昇格を、今すぐまとめて作る
- **理由**:
  - 「人を採用して、教えて、任せる範囲を広げる」（決定 `2026-11-13-ai-employee-agents-work-packs`）を、出社の画面の場所として見せられる。研修室は、研修中の AI社員がもともと居る場所なので、居場所と中身が一致する
  - 基盤 A：記憶と会話の記録を新しい外部の保存先に置かない（決定 `2026-10-24-workflow-runner-self-built` と同じ考え方）。道具を組織で絞った型つきの関数だけにでき、既存の決定 `2026-10-24-ai-calls-via-anthropic-sdk` にそのまま乗る
  - 昇格は任される範囲（権限）を広げる操作なので、人が決める。絞るのは安全な側なので自動でよい
- **却下案**:
  - 研修室は居場所だけのまま（決定 `2026-11-14-concept-and-flow` の前提）：育てる操作の置き場所が無く、会話の選択肢か通常の表示に散る
  - 研修室を、札とフロア案内からだけ入る場所にする（キーを足さない）：キーボードだけで使う人が入れない
  - Claude Managed Agents：ベータで、会話の記録が Anthropic 側に残る（Zero Data Retention の対象外）。法務・情報システム部門の確認が先に要る
  - 3段階の等級：分かりやすいが、任せる範囲の刻みが粗くなる
- **ほかの決定への影響**:
  - `2026-11-14-concept-and-flow` の「あとで決めること」の「研修室の使い方：AI社員の居場所だけの前提」は、この決定で「育てる場所」に決まった。「研修室・ラウンジ・充電ステーションは仕事の場所ではない」のうち、研修室は部屋になる（ラウンジと充電ステーションは居場所のまま）
  - `2026-11-13-ai-employee-agents-work-packs` の「まだ決まっていないこと」のうち、実行の基盤・モデル・等級と昇格はこの決定で決まった。読ませる資料の範囲・毎朝の処理との関係・給与・外部のパックに進む条件は #1114 に残る
- **ルール**:
  - 本番では、法務部門・情報システム部門の確認（#1114 の10）が済むまで、エージェントを環境変数のスイッチで止めておく。止まっている間、画面は「準備中」と書き、AI社員がしていないことをしたように見せない
  - 昇格のように任される範囲を広げる操作は、数字のキーだけでは通さない（決定 `2026-11-14-office-entry-same-site-only` の b と同じ考え方）
  - 実績は DB の事実だけから数える。エージェントの自己申告や作りごとの経験値を、等級の判定に使わない
- **実装で決めたこと**（#1188〜#1190、PR #1239）:
  - 研修中（`deskStatus` の `training`）は「オンボーディングを社長が承認していない、または役割の仕事が準備中」。等級（`ai_employees.level`）は研修室の API（`aiEmployees.training`）だけが返し、`OfficeEmployee` には足さない
  - 1回の要求で進めるのは「Claude の呼び出し1回＋道具の実行」だけ。会話は追記だけで、assistant の内容は受け取ったまま（思考のブロックを含めて）残す。行の鍵（`locked_until`、40秒）と段の数を1文の UPDATE で取る
  - 報告の道具は強制できない（`tool_choice` の any・tool はこのモデルで 400）ので、`strict: true` で出して指示文で求める。報告なしで止まったら促しを足し、2回までで `no_report` として終える
  - 上限：1セッション12回の呼び出し（失敗した呼び出しも数える）・出力4万トークン。1回の呼び出しは `max_tokens` 4,000・effort `low`・待ち20秒（`agent/runtime.ts` の `AGENT_CALL_TIMEOUT_MS`。ほかの AI の呼び出しと同じ）、1回の答えで書くノートは1つまでと指示する。呼ぶ前に `consumeAiCalls` を1回分通す
  - 1段の保存は、セッションの行をまだその段が持っていて `running` のときだけ行い、ノートもその後に書く（段の途中で取り消されたら、何も残さない）
  - 機能のスイッチは実行中のセッションにも効く：切れていれば `advance` は Claude を呼ばずに `disabled` を返す
  - セッションは専用の表（`ai_employee_sessions`）に置き、`flow_runs` には載せない。研修室の画面が秒単位で1段ずつ進める対話の作業で、定期実行で日単位に進めるワークフローとは目的が違うため。毎朝の処理（#1102）をエージェントにするときに決め直す（決定 `2026-11-13-ai-employee-agents-work-packs` の「#1114 で決め直す」の結論）
  - 拒否（`refusal`）は別のモデルに切り替えず、`refused` で終える（切り替えると、思考のブロックを読めないモデルに会話を渡すことになる）。社長はやり直せる
  - 記憶の道具は公式のページの返し方に合わせ、パスは `/memories/<名前>.md`（1段のフォルダまで）、1ファイル4,000字・20ファイル・合計3万字。メールアドレス・電話番号・鍵らしい文字列は書かせない。社長が直した・消したノートも版に残す
  - 社長の方針と訂正は、閉じられない区切り（`<president_policy>`・`<president_correction>`）の中のデータとして渡す。オンボーディングで読ませるのは職務記述書と方針だけ（リードも営業の手引きも読ませない）
  - 評価面談：最初の面談はオンボーディングの承認の直後から、そのあとは30日ごと。新しい面談を開くと、決まっていない古い面談はそのときの等級のまま閉じる（古い事実で昇格させない）。実行中の作業は数えない。実績は `ai_employee_runs` の事実だけで数え、提案の採用率は提案の記録ができるまで「記録なし」（その間は昇格を推薦しない）。昇格の基準（`PROMOTION_BARS`）と絞る基準（`NARROWING_BAR`）は**暫定**で、数字はオーナーに確かめる
  - 承認・昇格・方針の変更・自動で絞った等級は監査ログ（`resource: 'ai_employee'`、`metadata.event`）に残す。昇格は社長が見た等級（`fromLevel`）からだけ上げ、二重の送信では上がらない
  - ノートは書いたあとの全体を検査する（何回かの編集でメールアドレスを組み立てさせない）。全角の文字は NFKC で直してから見る。社長の方針と訂正にも同じ検査をかける
  - 研修室は特定の AI社員の部屋ではない（`ROOM_ROLES.training` は null、部屋には `guide: null` を渡す）。カメラは研修室の勉強机（`TRAINING_ROOM_SPOT`）に寄る。フロアの札で入れるのは研修室だけ（`ENTERABLE_AREAS`。ほかの部屋の札を扉にするかは別に決める）
  - 機能のスイッチは環境変数 `AI_EMPLOYEE_AGENT_ENABLED`（`'true'` のときだけ）。メンバーは研修室で等級と面談の数字だけを見られ、ノート・報告・方針は管理者だけが見る
- **まだ決まっていないこと**（オーナーに確かめる）:
  - 昇格の基準と絞る基準の数字（暫定）。成功した作業の回数（30日で20・60・120回）は、毎朝1回の作業では届かない。仕事を載せる #1102・#1103 の頻度と合わせて決める
  - 自動で絞るのは評価面談を開いたときだけ（スイッチが入っているときだけ）。日次の定期実行で絞るか
  - 仕事を載せるとき（#1102・#1103）、等級1以上の AI社員だけを実行するか（今は承認前の席は、実行があっても「研修中」と出る）
  - 会話の記録（`ai_employee_sessions.messages`。拒否された書き込みの文も含む）とノートの版の保存期間・消し方。解雇すると消える（cascade）ことの是非。#1114 の法務部門・情報システム部門の確認と合わせて決める
