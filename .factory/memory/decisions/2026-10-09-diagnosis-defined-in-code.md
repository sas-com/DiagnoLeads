### [Architecture] 診断はコードで定義し、点数はサーバー側でだけ計算する
- **日付**: 2026-10-09
- **決定**: AX マイグレーション診断は `lib/features/diagnostics/` に TypeScript で定義する（設問・選択肢・配点・判定ルール）。回答は `diagnostic_submissions` に保存し、作成・更新したリードと紐づける（#55、#46 の方針の具体化）
- **理由**:
  - MQL / SQL 判定や難易度の計算は、配点の合計だけでは表せないルールを含む
  - 判定ロジックを単体テストで固定でき、設問の版（`version`）と結果を一緒に保存できる
  - v1 は点数をクライアントから受け取っていて改ざんできた。その弱点を引き継がない
- **ルール**:
  - お客様に返すのは難易度・緊急度・主な課題・推奨ステップだけ。リードスコア・MQL/SQL 判定は返さない
  - 業務側で「要確認」の基準は `ax-migration/config.ts` に集める
  - 公開フォームは本人確認ができないため、同じメールアドレス（大文字小文字は区別しない）の既存リードは**書き換えない**。回答は既存リードに紐づけて保存し、営業には「本人未確認」として既存の登録名で通知する（2026-10-09 レビュー指摘: 第三者が他人のメールで回答するとリードを改ざんできた）
  - 同じメールの同時送信は (組織, メール) の advisory lock で直列化し、リードの重複を防ぐ
  - Web診断の完了を MQL の「行動」に数える（2026-10-09 オーナー判断）。config で「MQL候補」止まりにも切り替えられる → 2026-10-16 廃止（#139「適合」と「関心あり」）
  - 移行対象は基幹システムに加えて、VB のクライアントサーバー型、Access（部署単位のツールを含む）、WebPerformer（ローコードはまず WebPerformer のみ）。それぞれ別の選択肢・対象システムとして扱う。その他のローコード製品は当面対象外（2026-10-09 オーナー判断）
- **却下案**: Payload の DiagnosticForms に配点を持たせる（判定ルールを表現できず、テストもしにくい）。Payload は今後もブログ・LP など文章コンテンツに使う
