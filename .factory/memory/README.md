# MemoryBank

AI エージェント（Claude Code・Factory Droid など）が、セッションをまたいで一貫した判断をするための記録。リポジトリは公開なので、秘密情報と社外秘（取引先名・単価・営業の手引きの本文）は書かない。

---

## ファイル構成

| 場所 | 中身 | いつ読むか |
|------|------|-----------|
| `decisions/` | 意思決定（1件1ファイル）。書き方は `decisions/README.md` | 索引はセッション開始時（Claude Code はフックが出す。ほかは `bun run memory:index`）。本文は作業に関係するとき |
| `violations.md` | 原則違反の記録と再発防止策 | 再発防止策は CLAUDE.md の「毎回守ること」とフックに入っているので、記録は違反の経緯を知りたいときに読む |
| `learnings.md` | 起きた問題と解決策、うまくいったやり方 | 似た問題に当たったとき |
| `preferences.md` | オーナーの好み | 作業の進め方・報告の仕方を決めるとき |
| `decisions.md` | 移動の案内だけ（2026-10-24 に `decisions/` へ分けた） | 読まなくてよい |

Claude Code では、読んだ・編集したファイルに関係する決定（各決定の `paths`）をフックが知らせる（`.claude/hooks/post-tool-decisions.ts`）。

---

## 書くとき

| 起きたこと | 書く場所 |
|-----------|---------|
| 重要な意思決定をした（技術選定・設計・プロセス・オーナー判断） | `decisions/` に1ファイル足す。置き換えるときは古い方を `superseded` にする |
| 原則に違反した | `violations.md` に記録し、再発防止策を CLAUDE.md かフック（`.claude/hooks/`）に入れる |
| 問題を解決した・学びがあった | `learnings.md` |
| PR のレビューの指摘・CI の失敗・手戻り・オーナーの訂正があった | 教訓を取り出して `learnings.md` に差分で足す（スキル `record-decision`）。原則違反なら `violations.md` に書き、`learnings.md` には重ねない |
| 学びに従って作業した | PR の本文の「役立った学び／外れた学び」の節に、`- 役立った：<見出し>` か `- 外れた：<見出し>（理由）` を1行ずつ書く（`learnings.md` の評価の数は、月1回の見直しで数える） |
| オーナーの好みが分かった | `preferences.md` |

- 学びは差分で足す。ファイル全体や節をまとめて書き直したり、教訓を短く言い直したりしない（具体的な中身が落ちる。決定 `2026-11-12-memory-ace-grow-and-refine`）。長くなった経緯は、PR へのリンクに置き換えてよい

- 「最終更新」の行は書かない（並行するセッションの衝突の元。日付は git にある）
- 書く前に、公開されてよい内容かを確かめる（2026-10-15 に本番 DB の接続情報をここに書いてしまった。違反の記録を参照）

## メンテナンス（月1回）

毎月1日に、GitHub Actions（`.github/workflows/memory-review.yml`）が `memory-review` ラベルの Issue を開く。Issue には、前の月にマージされた PR の本文から集めた「役立った・外れた」の行と、`learnings.md` の大きさが入っている。Issue のやることを進め、結果（数えた件数・適用した整理・行数）をコメントに書いて閉じる（決定 `2026-11-12-memory-review-monthly-issue`）。

- 古くなった決定を `superseded` にする。`paths` がずれていれば直す（ずれはユニットテストが検出する）
- 学びを整理する（決定 `2026-11-12-memory-ace-grow-and-refine`）
  1. 数える：Issue に集めた行を、`learnings.md` の見出しと突き合わせ、各項目の「評価」の数と PR 番号を増やす。この更新は承認なしで、整理の PR に入れてよい
     - 見出しが一致しない行（言い換え・誤記）は、どの項目のことかを人が確かめてから数える
     - 「評価」の行にすでにある PR 番号は数えない（二重に数えない）
     - Issue を手で作るときの集め方：`gh api -X GET search/issues --paginate -f q='repo:sas-com/DiagnoLeads is:pr is:merged merged:<開始日>..<終了日>' -f per_page=100` の本文から、`- 役立った：` か `- 外れた：` で始まる行（「なし」を除く）を抜き出す
  2. 候補を出す（ファイルはまだ変えない。Issue に書く）
     - 重複（読む人が取る行動が同じ）
     - 「外れた」が「役立った」より多い学び
     - 今のコード・有効な決定・CLAUDE.md と合わなくなった学び
     - 公開に適さない記述（取引先名・単価・営業の手引きの本文など）
     - 機械で判定でき、同じ学びへの追記か再発が2回以上ある学び（追記の回数は `git log -p -- .factory/memory/learnings.md` で数える）
  3. オーナーに候補を見せ、承認された分だけ PR で適用する
     - PR を出す前に、`learnings.md` を変えている open な PR を確かめ、先にマージしてもらうか待つ（同じ行で衝突するため）
     - まとめる・消す・見出しを変える前に、参照元を探す：`grep -rn '<見出しの一部>' .factory/memory .claude CLAUDE.md docs`。参照元も一緒に直す
     - 重複はまとめる。まとめるときも、それぞれの具体的な手順・数字は残し、評価の数は足し合わせる。まとめた後、元の項目と1行ずつ突き合わせ、当てはまる範囲が変わっていないか確かめる（学び「[Process] リファクタリングで決まりが変わっていないかは、言葉の機械的な突き合わせでは確かめられない」）
     - 外れた学び・合わなくなった学びは直すか消す。消した理由を PR の本文に書く（原文は git の履歴に残る）
     - 機械で判定できる学びは Issue にして、フックかテストに移す（決定 `2026-10-24-claude-harness-guards`）
  - 評価の数は、まとめるときの足し合わせのほかは減らさない・0に戻さない
- Claude Code の `/doctor prompt-audit`（CLAUDE.md と `.claude/`）と `/doctor prompt-audit .factory/memory`（記録。既定の対象外なのでパスを渡す）で、古い・矛盾した指示を探す
- Anthropic の公式の変更（Claude Code の変更履歴、モデルの提供終了の予定）を確かめ、CLAUDE.md・`.claude/`・`lib/features/ai/` を見直す（スキル `official-check`）
